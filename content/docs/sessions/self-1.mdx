## 1단계 복습과 화면 익히기

이 단계를 마치면 수업 때 강사를 따라 누르던 화면을 혼자서 설명할 수 있습니다.

<DeepDive title="Claude 데스크톱 앱의 Code 탭, 하나씩 짚어 보기">

| 위치 | 이름 | 하는 일 |
| --- | --- | --- |
| 사이드바 위쪽 | **Code** 탭 | Claude Code 작업 공간입니다. 채팅 탭과 다른 곳입니다. 탭이 아이콘으로만 보이면 마우스를 올려 이름을 확인합니다 |
| 입력창 아래 줄, 첫 칸 | 환경 선택 | 어디에서 일할지 고릅니다. 내 PC의 폴더로 일하려면 **Local** 묶음의 맨 위 항목입니다 |
| 그 옆 | 폴더 칸 | <b>Open folder…</b>로 이번 대화의 작업 폴더를 정합니다. 가장 중요한 안전장치입니다 |
| 같은 줄 | 모드 칸 | 얼마나 스스로 하게 둘지 고릅니다(아래 표) |
| 같은 줄 오른쪽 | 모델 선택 | 어떤 모델로 일할지 고릅니다. 처음에는 기본값 그대로 둡니다 |
| 아래 가운데 | 입력창 | 지시를 쓰고 Enter로 보냅니다. `@` 뒤에 파일 이름을 쓰면 그 파일을 짚어 줄 수 있고, **+** 버튼이나 끌어다 놓기로 파일을 붙일 수 있습니다 |
| 대화 중 | 권한 요청 | 무엇을 바꾸려는지 보여 주고 허락을 구합니다. 읽고 허용하거나 거부합니다 |
| 작업 중 | 멈춤 버튼 | 누르면 바로 멈춥니다(<Kbd keys="esc" />도 같습니다). 멈추지 않고 고칠 말을 써서 보내도 다음 행동부터 반영합니다 |
| 사이드바 | 대화 목록 | 대화 하나하나가 따로 저장됩니다. **+ New**로 새 대화를 열고, 지난 대화를 눌러 이어서 할 수 있습니다 |

모드 칸의 네 가지는 이렇게 다릅니다.

| 모드 | 동작 | 이럴 때 |
| --- | --- | --- |
| **Manual** | 파일을 고치거나 명령을 실행하기 전에 매번 묻습니다 | 처음 배울 때, 중요한 폴더 |
| **Accept edits** | 파일 고치기와 폴더 만들기·옮기기 같은 흔한 파일 작업은 묻지 않고, 그 밖의 명령은 묻습니다 | 계획을 이미 확인한 뒤 |
| **Plan** | 파일을 읽고 살펴본 뒤 계획만 내놓습니다. 승인하기 전에는 파일을 고치지 않습니다 | 여러 파일이 바뀌는 일, 처음 해 보는 일 |
| **Auto** | 일일이 묻지 않고, 위험해 보이는 행동인지 뒤에서 점검합니다. 계정과 모델에 따라 보이지 않을 수 있습니다 | 익숙해진 뒤, 가상 데이터로 |

예전 버전에서는 이 모드들이 Ask permissions, Auto accept edits, Plan mode라는 이름이었습니다. 앱은 자주 바뀌니 이름이나 위치가 다르면 [공식 문서](https://code.claude.com/docs/en/desktop)를 확인하세요.

</DeepDive>

<Callout title="대화 하나에는 일 하나만">

</Callout>

## 2단계 지시를 바꾸면 결과가 바뀐다

이 단계를 마치면 같은 일을 두 가지로 시켜 보고, 무엇이 결과를 바꿨는지 말할 수 있습니다. AI에게 주는 지시문을 <Term id="prompt">프롬프트</Term>라고 합니다.

<DeepDive title="좋은 지시의 네 가지 조건">

학생에게 수행평가를 안내할 때와 같습니다. "보고서 써 오세요"보다 "A4 2쪽, 표 1개 넣고, 출처를 밝혀서, 금요일까지"가 좋은 안내인 이유를 떠올려 보세요.

1. **대상이 분명하다** — "파일들"이 아니라 "이 폴더의 받은 공문 PDF", "@제목 없음.xlsx"
2. **결과 모양이 있다** — "표로", "기한이 빠른 순서로", "파일로 저장"
3. **하지 말 것이 있다** — "지우지 마", "아직 옮기지 마", "지어내지 마"
4. **확인 기준이 있다** — "개수가 맞는지 세어줘", "찾지 못하면 '확인 필요'로"

흔한 오해가 하나 있습니다. 길고 공손하게 쓴다고 좋은 지시가 되지는 않습니다. 네 가지가 들어 있으면 짧은 반말 한 문장으로도 충분합니다. 2회차에서는 이것을 목적·입력·출력·조건·검증의 5요소로 넓힙니다.

</DeepDive>

## 3단계 계획 보기와 되돌리기

이 단계를 마치면 언제 계획부터 받을지 가릴 수 있고, 잘못됐을 때 무엇이 되돌아오고 무엇이 되돌아오지 않는지 압니다.

<DeepDive title="플랜 모드, 언제 쓰고 언제 안 써도 되나">

| 이런 일이면 | 플랜 모드 | 이유 |
| --- | --- | --- |
| 파일 여러 개를 옮기거나 이름을 바꿈 | **쓴다** | 한 번에 많이 바뀌고 되돌리기 번거롭다 |
| 처음 해 보는 일, 방법을 모르겠음 | **쓴다** | 계획을 읽으면서 방법을 배울 수 있다 |
| 표 하나 보여 주기, 요약하기 | 안 써도 됨 | 아무 파일도 바뀌지 않는다 |
| 오탈자 하나 고치기 | 안 써도 됨 | 한 문장으로 설명되는 작은 일 |

모드를 바꾸지 않고 문장에 <b>"아직 실행하지 말고 계획만 보여줘"</b>라고 써도 비슷한 효과가 납니다. 다만 모드는 장치이고 문장은 부탁입니다. 중요한 폴더에서는 둘 다 쓰는 것이 안전합니다. 플랜 모드에서 계획을 승인하면 그때부터 파일을 고치기 시작합니다.

</DeepDive>

<DeepDive title="되돌리기: 무엇이 돌아오고, 무엇이 안 돌아오나">

수업에서 "옮긴 파일은 말로 되돌린다"고 한 데는 이유가 있습니다. Claude Code의 되돌리기 기능(체크포인트)은 **Claude가 파일 편집 도구로 쓰거나 고친 파일**을 기억해 두는 장치입니다. 명령으로 옮기거나 이름을 바꾼 파일은 따라오지 않을 수 있습니다 ([공식 문서 — Checkpointing](https://code.claude.com/docs/en/checkpointing)).

| 상황 | 방법 | 알아 둘 점 |
| --- | --- | --- |
| 작업 도중에 멈추고 싶다 | 멈춤 버튼 또는 <Kbd keys="esc" /> | 대화는 남습니다. 이어서 고칠 말을 하면 됩니다 |
| AI가 쓰거나 고친 문서를 이전 내용으로 | 입력창에 `/rewind` | 지시를 보낼 때마다 되돌아갈 지점이 생깁니다. 지점을 고르고 파일을 되살리는 항목을 선택합니다 |
| 옮기거나 이름을 바꾼 파일을 원래대로 | 말로 요청 + 이동 기록 | "이동기록.md를 보고 원래 자리로 되돌려줘". 그래서 기록을 남기게 합니다 |
| 완전히 꼬였다 | 사본을 버리고 다시 시작 | 실습은 zip을 다시 풀면 됩니다. 실제 업무에서도 원본은 두고 사본에서 일합니다 |
| 며칠 전 상태로 돌아가고 싶다 | Git | 3회차에서 배우는 세이브 포인트입니다 |

`/rewind` 메뉴의 모양은 앱 버전에 따라 다를 수 있습니다. 터미널에서는 입력창이 비어 있을 때 Esc를 두 번 누르면 같은 메뉴가 열립니다. 데스크톱 앱에서 메뉴가 열리지 않으면 말로 되돌려 달라고 하세요.

</DeepDive>

파일 탐색기에서 직접 확인하세요. 처음 상태로 완전히 돌아가고 싶으면 [옮긴 파일을 원래 자리로 되돌리기](/prompts/undo-moves) 프롬프트를 씁니다.

<Step id="m1-8" title="AI가 쓴 문서를 되돌려 보기">

이번에는 Claude가 직접 쓴 파일로 되돌리기 기능을 시험합니다. 먼저 "지금 폴더 상태를 폴더현황보고.md로 저장해줘"라고 시켜 문서를 하나 만든 다음, 일부러 망가뜨립니다.

이 단계를 마치면 자료를 읽혀 가정통신문 초안을 받고, 한글(HWP) 문서를 맡기고 돌려받는 현실적인 방법을 압니다.

Claude Code는 코드만 쓰는 도구가 아닙니다. 폴더의 자료를 읽고 **안내문, 요약, 일정표 같은 문서**도 파일로 써 줍니다. 다만 초안은 초안입니다. 내보내기 전에 담당 교사가 끝까지 읽고, 학교의 결재 절차를 그대로 밟습니다.

<DeepDive title="한글(HWP) 파일 다루는 법: 맡길 때와 돌려받을 때">

학교 문서는 대부분 <Term id="hwp">한글(HWP)</Term> 파일인데, HWP는 속을 바로 읽기 어려운 형식(바이너리)이라 Claude Code가 그대로는 읽지 못하는 경우가 있습니다. 요령은 하나입니다. **한글에서 다른 형식으로 저장한 사본을 넘깁니다.** 원본은 그대로 둡니다.

**맡길 때** — 한글의 [파일 → 다른 이름으로 저장하기]에서 파일 형식을 고릅니다.

| 저장 형식 | 이럴 때 | 알아 둘 점 |
| --- | --- | --- |
| **PDF** | 읽히기만 하면 될 때(요약, 기한 뽑기, 대조). 가장 무난합니다 | 표가 복잡하면 칸의 글자 순서가 섞여 읽힐 수 있습니다. 먼저 제대로 읽었는지 확인합니다 |
| **워드 문서(\*.docx)** | 제목·문단·표의 구조를 살려 읽히고 싶을 때 | 글꼴과 줄 간격은 원본과 달라질 수 있습니다 |
| **한/글 표준 문서(\*.hwpx)** | 한글 형식을 그대로 두고 싶을 때 | <Term id="hwpx">HWPX</Term>는 ZIP 묶음 안에 XML이 든 개방형 형식이라 기계가 읽기 쉽습니다. 다만 Claude Code가 늘 깔끔하게 읽는다고 장담할 수는 없으니, 읽은 내용을 꼭 확인하고 잘 안 되면 PDF로 바꿉니다 |
| **텍스트 문서(\*.txt)** | 글자만 있으면 될 때 | 표와 서식이 사라집니다 |

파일 이름의 확장자만 `.hwpx`나 `.txt`로 바꾸는 것은 변환이 아닙니다. 반드시 한글에서 저장하세요. 한컴의 안내로는 HWPX가 국가표준(KS X 6101)인 OWPML을 따르는 개방형 형식이고, 기본 저장 형식은 [도구 → 환경 설정 → 파일]에서 바꿀 수 있습니다 ([한컴 지원센터 — HWPX 자주 묻는 질문](https://www.hancom.com/support/faqCenter/faq/detail/2784), [한컴테크 — HWPX 포맷 구조](https://tech.hancom.com/hwpxformat/), [한컴 도움말 — 다른 이름으로 저장하기](https://help.hancom.com/hoffice120/ko-KR/Hwp/file/save_as/save_as.htm)). 메뉴 이름은 한글 버전에 따라 조금 다를 수 있습니다.

**돌려받을 때** — Claude Code에게 HWP 파일을 직접 만들어 달라고 하기보다, 아래 순서가 현실적입니다.

1. **글만 받아서 양식에 붙여 넣기 (권장).** 로고, 문서 번호, 학교장 이름 칸은 학교 양식에 이미 있습니다. AI에게는 기호를 뺀 글만 받아 한글 양식의 본문 자리에 붙여 넣습니다. 붙여 넣을 때 형식을 묻는 창이 뜨면 글자만 붙이는 쪽을 고릅니다.
2. **표는 한글에서 직접 만들고 내용만 옮기기.** 칸 너비와 테두리까지 맞춰 받으려 애쓰는 것보다 빠릅니다.
3. **워드(DOCX)로 받아 한글에서 열기.** 문서 전체의 틀이 필요하면 "docx로 저장해줘"라고 한 뒤 한컴오피스에서 열어 한글 형식으로 다시 저장합니다. 표와 글꼴은 손봐야 할 수 있고, Claude Code가 워드 파일을 만들려면 Python 같은 도구가 필요할 수 있습니다(2회차에서 준비합니다).

**하지 않는 것**

- 학생 정보가 든 한글 문서는 형식을 바꿔도 넘기지 않습니다. 명렬표, 성적, 상담 기록, 생기부가 그렇습니다.
- 검색해서 나온 변환 사이트에 학교 문서를 올리지 않습니다. 문서가 누구의 서버로 가는지 알 수 없습니다.
- Claude Code가 한글 파일을 읽으려고 변환 프로그램을 설치하겠다고 하면, 무엇인지 확인하기 전에는 승인하지 않습니다. 이 과정은 확인되지 않은 변환 도구를 권하지 않습니다.
- 저장한 사본을 Claude Code가 열지 못한다면 학교 PC의 문서보안 프로그램이 파일을 잠갔을 수 있습니다. 우회하지 말고 전산 담당 선생님과 상의하세요.

</DeepDive>
