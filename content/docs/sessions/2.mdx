## 개념

### 네 단계로 일 시키기

Claude Code는 맥락을 모으고, 실행하고, 결과를 확인하는 일을 되풀이합니다([How Claude Code works](https://code.claude.com/docs/en/how-claude-code-works)). 공식 문서는 복잡한 일은 Plan에서 시작해 접근 방법부터 받아 보고([데스크톱 앱 문서](https://code.claude.com/docs/en/desktop)), 결과를 Claude가 직접 확인할 수단을 주라고 권합니다([Best practices](https://code.claude.com/docs/en/best-practices)). 네 단계로 정리하면 이렇습니다.

| 단계 | AI가 하는 일 | 교사가 하는 일 | 모드 |
| --- | --- | --- | --- |
| 1. 탐색 | 파일을 읽고 상황 파악 | 무엇을 볼지 알려 주기 | Plan |
| 2. 계획 | 어떻게 할지 제안 | **읽고, 고치고, 승인** | Plan |
| 3. 실행 | 파일을 만들고 계산하기 | 권한 요청 확인 | 계획 승인 뒤 |
| 4. 검증 | 기준대로 확인하고 증거 보여 주기 | **기준을 정하고 결과 확인** | 계획 승인 뒤 |

굵게 쓴 두 칸, 계획 승인과 결과 확인이 교사가 책임지는 자리입니다.

**<Term id="plan-mode">플랜 모드</Term>**에서는 파일을 읽기만 하고 고치지 않습니다. 데스크톱 앱은 입력창 아래 줄의 모드 칸에서 **Plan**을 고르고, 터미널은 <Kbd keys="shift+tab" />을 누르거나 요청 앞에 `/plan`을 붙입니다(메뉴가 다르게 보이면 [권한 모드 문서](https://code.claude.com/docs/en/permission-modes) 참고). 오탈자 고치기처럼 한 문장으로 끝나는 일은 계획 없이 바로 시켜도 됩니다.

<Analogy title="수업 지도안에 빗대면">
  학습자와 교재를 살피고(탐색), 지도안을 쓰고(계획), 수업을 하고(실행), 형성평가로 목표에 닿았는지 봅니다(검증). 지도안 없는 수업과 평가 없는 수업이 불안하듯, 계획과 검증이 빠진 AI 작업도 불안합니다.
</Analogy>

### 업무 프롬프트 5요소

평가계획서에 평가 목적, 대상, 방법, 유의 사항, 채점 기준이 빠지지 않듯이, AI에게 일을 맡길 때도 빠지면 안 되는 다섯 칸이 있습니다. <Term id="five-elements">업무 프롬프트 5요소</Term>입니다. 깊이 파기 1.5에서 본 좋은 지시의 네 가지(대상, 결과 모양, 하지 말 것, 확인 기준)에 "왜 하는가"를 더해 넓힌 것입니다.

| 요소 | 묻는 것 | 평가계획서로 치면 | 오늘 실습의 예 |
| --- | --- | --- | --- |
| 목적 | 왜 하는가 | 평가 목적 | 반별 점수를 모아 교과협의회 자료로 |
| 입력 | 무엇을 가지고 | 평가 대상과 자료 | `수행평가_점수` 폴더의 엑셀 6개 |
| 출력 | 무엇을 만들어 | 산출물 | 전체 명단과 반별 평균이 든 엑셀 1개 |
| 조건 | 지켜야 할 것은 | 유의 사항 | 원본 수정 금지, 이상한 값은 고치지 말고 표시 |
| 검증 | 맞는지 어떻게 아나 | 채점 기준 | 반별 인원·합계를 원본과 대조한 검산표 |

### CLAUDE.md, AI에게 주는 인수인계서

실습을 하다 보면 "원본은 고치지 마", "결과는 새 파일로"를 여러 번 말하게 됩니다. 이런 말을 폴더의 <Term id="claude-md">CLAUDE.md</Term> 파일에 적어 두면 Claude가 대화를 시작할 때마다 읽습니다. 새로 온 동료에게 "우리 학교, 내 업무에서는 이렇게 합니다"를 적어 건네는 인수인계서입니다.

```markdown title="CLAUDE.md 예시"
# 새봄고 1학년 국어 수행평가 작업 규칙
- 답과 파일은 모두 한국어로
- 원본 파일은 고치지 않는다. 결과물은 '결과' 폴더에 새 파일로 만든다
- 점수나 기록에서 이상한 값을 찾으면 고치지 말고 표로 보고한다
- 파일을 지우거나 이름을 바꾸기 전에는 목록을 먼저 보여 준다
- 실제 학생의 이름·성적이 든 파일은 다루지 않는다
```

<Callout title="짧게, 그리고 구체적으로">
  CLAUDE.md는 잠금장치가 아니라 Claude가 참고하는 지침이고, 구체적이고 짧을수록 잘 지켜집니다([공식 문서](https://code.claude.com/docs/en/memory)). "형식을 잘 맞춰"보다 "날짜는 YYYY-MM-DD"가 낫습니다. 넣을 것과 뺄 것을 가리는 법은 [깊이 파기 2.5](/sessions/self-2#5단계-claudemd-다듬기와-3회차-준비)에서 다룹니다.
</Callout>

### 컨텍스트 비우기와 되돌리기

<Term id="context">컨텍스트</Term>는 AI가 지금 대화에서 보고 있는 내용 전체입니다. 책상에 지난 일의 서류가 쌓이면 지금 일의 서류를 찾기 어렵듯, 관계없는 내용과 실패한 시도가 쌓이면 답이 흐려집니다.

| 조작 | 하는 일 |
| --- | --- |
| <Kbd keys="esc" /> | 작업을 멈춥니다. 대화는 그대로 남습니다 |
| <Term id="clear">`/clear`</Term> | 대화를 비우고 새로 시작합니다. 파일과 CLAUDE.md는 그대로입니다 |
| <Term id="rewind">`/rewind`</Term> | 대화와 Claude가 고친 파일을 이전 요청 시점으로 되돌리는 메뉴를 엽니다 |
| `@파일이름` | 특정 파일을 직접 가리킵니다 |

입력창에 `/`를 치면 지금 쓸 수 있는 명령 목록이 나옵니다(환경에 따라 다를 수 있습니다). 데스크톱 앱에서 <Kbd keys="esc" />는 멈춤입니다. <Kbd keys="esc" />를 두 번 눌러 되돌리기 메뉴를 여는 것은 터미널에서의 동작입니다.

<Callout type="warn" title="같은 실수를 두 번 고쳤는데도 틀린다면">
  세 번째로 고쳐 달라고 하지 말고 `/clear`로 비운 뒤, 알게 된 점을 넣은 더 구체적인 요청 하나로 새로 시작하세요([Best practices](https://code.claude.com/docs/en/best-practices)).
</Callout>

<DeepDive title="되돌리기(/rewind)는 어디까지 되나">

`/rewind`가 되돌리는 것은 **Claude가 편집 도구로 쓰거나 고친 파일**입니다(문서, 코드, 오늘 만들 HTML 계산기). 명령을 실행해서 생긴 변화, 곧 프로그램을 돌려 만든 엑셀 결과물이나 한꺼번에 바꾼 파일 이름은 `/rewind`로 돌아오지 않습니다([Checkpointing](https://code.claude.com/docs/en/checkpointing)). 1회차에서 파일을 옮길 때 이동 기록을 남기고 말로 되돌린 것도 같은 이유입니다([깊이 파기 1.5](/sessions/self-1#3단계-계획-보기와-되돌리기)). 그래서 오늘은 "원본은 고치지 않고 결과는 새 파일로", "이름 바꾸기는 사본 폴더에서, 이름표를 남기고"를 규칙으로 삼습니다. 폴더 전체를 되돌리는 더 든든한 안전망은 3회차의 <Term id="git">Git</Term>입니다.

</DeepDive>

### 검증 기준은 사람이 정한다

채점 기준표 없이 "잘 쓴 글에 높은 점수를 주세요"라고 하면 채점자마다 점수가 달라집니다. AI도 기준이 없으면 "끝난 것처럼 보이는" 데서 멈추고, 기준을 주면 그 기준으로 스스로 확인하고 고칩니다. 이것이 <Term id="verify">검증</Term>입니다.

| 기준을 주는 방법 | 이렇게 말합니다 | 언제 |
| --- | --- | --- |
| 대조 | "원본 합계와 다시 계산한 합계를 나란히 보여 줘" | 합치기, 옮기기 |
| 개수 | "낸 학생 수와 안 낸 학생 수를 더하면 명단 인원과 같은지" | 명단 대조, 중복 제거 |
| 정답을 아는 예 | "'가나다'를 넣으면 9바이트가 나와야 해" | 계산 도구 |

"확인했습니다"라는 말 대신 **증거**(검산표, 계산 과정)를 보여 달라고 하세요. 점수와 기록의 최종 확인은 교사가 합니다. AI의 검산은 그 확인을 쉽게 해 주는 보조입니다.

## 실습

[자료실](/downloads)에서 **2회차 실습 자료**(`session2-practice.zip`)를 내려받아 압축을 풀고, 1회차와 같은 방법으로 Claude Code에서 `2회차_실습자료` 폴더를 엽니다. 새봄고등학교 1학년 국어 '논설문 쓰기' 수행평가(내용·구성·표현 각 10점, 30점 만점) 자료가 들어 있습니다.

<Callout type="warn" title="점수 파일은 가상 데이터입니다. 실제 성적 파일로 하고 싶어지는 바로 지금이 멈출 때입니다">
  실습이 잘 되면 "우리 반 실제 점수로 해 보고 싶다"는 생각이 듭니다. 하지 마세요. 실제 학생의 이름·학번·성적이 든 파일과 나이스(NEIS)에서 내려받은 원본은 AI에 넣지 않습니다. 이름을 번호나 코드로 바꾸는 <Term id="pseudonymize">가명 처리</Term>와 학교·교육청 지침에 따른 판단 기준은 4회차와 깊이 파기 4.5에서 다룹니다. 그때까지는 가상 데이터로 도구를 만들고 검증하는 데 집중합니다.
</Callout>

아래 예상 결과의 숫자는 실습 자료와 맞춰 두었습니다. AI가 쓰는 문장과 표 모양은 할 때마다 조금씩 다릅니다. **모양이 아니라 숫자가 같은지**를 보세요.
