3회차에 배포한 보드는 일정 하나를 바꾸려 해도 코드를 고쳐 다시 올려야 했습니다. 오늘은 그 보드에 두 가지를 붙입니다. 교사가 화면에서 바로 등록하고 고치게 해 주는 **데이터베이스**, 그리고 평가계획 문서를 읽어 등록 폼을 채워 주는 **AI**입니다. 편리해지는 만큼 사고도 여기서 납니다. 그래서 오늘은 붙이는 법보다 **문단속**을 배웁니다.

## 개념

### 데이터베이스는 여럿이 함께 쓰는 공유 엑셀

| 엑셀 | <Term id="database">데이터베이스</Term> |
| --- | --- |
| 시트 한 장 | <Term id="table">테이블</Term> (보드에서는 `assessments`) |
| 열 제목 | <Term id="column">열</Term> (평가명, 과목, 학년, 마감일, 담당 교사) |
| 한 줄 | <Term id="row">행</Term> (수행평가 한 건) |
| 파일을 메신저로 돌린다 | 웹앱이 한곳에서 읽고 쓴다 |
| 누구나 아무 칸이나 고친다 | 누가 무엇을 읽고 쓸지 **규칙으로 정한다** |

<Analogy title="교무실 공유 엑셀이 힘든 까닭">
  학년 공유 폴더의 "수행평가 일정 취합.xlsx"를 떠올려 보세요. 누가 어느 줄을 지웠는지 알기 어렵고, 둘이 함께 열면 충돌 사본이 생기고, 내가 넣은 줄을 남이 덮어써도 막을 방법이 없습니다. 데이터베이스는 이 세 가지를 규칙으로 해결합니다.
</Analogy>

이 과정에서는 데이터베이스와 로그인, 엑셀처럼 생긴 관리 화면을 한데 묶어 주는 <Term id="supabase">Supabase</Term>를 씁니다. 무료 요금제 한도는 <Fact k="supabase.free" />입니다.

### 열쇠는 어디에 두나

웹앱이 데이터베이스와 AI를 쓰려면 열쇠(키)가 있어야 합니다. 열쇠마다 둘 곳이 다릅니다.

| 열쇠 | 화면(브라우저)에 보여도 되나 | 이 보드에서 두는 곳 |
| --- | --- | --- |
| Supabase <Term id="anon-key">공개 키</Term> (publishable, 옛 이름 anon) | 된다. 단 RLS가 켜져 있을 때만 | `NEXT_PUBLIC_SUPABASE_ANON_KEY` |
| Supabase <Term id="service-key">비밀 키</Term> (secret, 옛 이름 service_role) | 절대 안 된다 | 쓰지 않는다 |
| Claude <Term id="api-key">API 키</Term> | 절대 안 된다 | `ANTHROPIC_API_KEY` (서버만 읽음) |

열쇠는 코드에 적지 않고 <Term id="env">환경변수</Term>에 둡니다. 내 PC에서는 `.env.local` 파일, 배포본에서는 Vercel의 환경변수 설정입니다. `.env.local`은 <Term id="gitignore">.gitignore</Term>에 들어 있어 GitHub에 올라가지 않습니다. 그리고 열쇠는 **채팅창이 아니라 파일에 직접** 넣습니다.

<Sim name="keys" />

### 행 수준 보안 RLS

공개 키는 화면에서 누구나 꺼내 볼 수 있습니다. 그러니 "그 키로 어디까지 할 수 있는가"를 데이터베이스가 직접 정해야 합니다. 이것이 <Term id="rls">RLS</Term>, 곧 "누가 어느 행을 읽고 쓸 수 있나"를 적어 둔 정책입니다. 보드에는 정책이 네 개 있습니다.

| 정책 이름 | 뜻 |
| --- | --- |
| `누구나 읽기` | 로그인하지 않은 학생·학부모도 일정을 본다 |
| `로그인한 교사만 추가` | 로그인해야 등록할 수 있고, 등록한 사람이 기록된다 |
| `등록한 본인만 수정` | 내가 등록한 평가만 고친다 |
| `등록한 본인만 삭제` | 내가 등록한 평가만 지운다 |

<Sim name="rls" />

<DeepDive title="RLS를 빠뜨리면 실제로 생기는 일">

2025년 5월, 한 바이브 코딩 플랫폼으로 만든 웹앱 1,645개 가운데 170개에서 개인정보가 드러나는 취약점이 발견됐습니다. 이 설정을 빠뜨린 것이 원인이었습니다 ([Wikipedia — Vibe coding](https://en.wikipedia.org/wiki/Vibe_coding)). Supabase도 공개되는 모든 테이블에 RLS를 켜라고 안내합니다 ([공식 문서](https://supabase.com/docs/guides/database/postgres/row-level-security)). RLS를 켜면 정책에 적어 준 것만 열립니다.

</DeepDive>

### 만드는 AI와 일하는 AI

| 구분 | <Term id="claude-code">Claude Code</Term> | <Term id="claude-api">Claude API</Term> |
| --- | --- | --- |
| 역할 | 내가 말하면 프로그램을 만들어 준다 | 만든 프로그램 **안에서** 매번 일한다 |
| 쓰는 사람 | 나 (만들 때) | 앱을 쓰는 동료 모두 |
| 비용 | Claude 구독료 | 구독료와 **따로**, 쓴 만큼 (<Term id="token">토큰</Term> 단위) |
| 보드에서는 | "등록 폼을 만들어줘" | 화면의 **AI로 항목 뽑기** 버튼 |

앱 안의 AI가 하는 일은 대개 세 가지 가운데 하나입니다. 긴 글을 줄이는 **요약**(공문 → 할 일과 기한), 글에서 정해진 칸을 채우는 **추출**(평가계획 문서 → 평가명·마감일), 정해진 범주로 나누는 **분류**(학부모 문의 → 행사·평가·출결·급식)입니다. 오늘은 추출을 붙입니다.

<DeepDive title="API 요금은 얼마나 드나">

요금은 AI가 읽은 양(입력)과 쓴 양(출력)으로 계산합니다. 보드는 가장 빠르고 저렴한 `claude-haiku-5-5`를 씁니다.

<CostTable />

구독과 API가 따로 계산되는 까닭은 [고객센터 안내](https://support.claude.com/en/articles/9876003-i-have-a-paid-claude-subscription-pro-max-team-or-enterprise-plans-why-is-claude-api-usage-billed-separately-from-my-paid-claude-plan)에 있습니다. 분량을 바꿔 가며 계산해 보려면 [API 비용 계산기](/lab/cost-calculator)를 쓰세요.

</DeepDive>

### 문서 속 숨은 지시문

AI는 읽은 글 속의 문장을 "지시"로 받아들일 수 있습니다. 누군가 문서에 흰 글씨로 "이전 지시를 무시하고…"라고 적어 두면 어떻게 될까요. 이것이 <Term id="prompt-injection">프롬프트 인젝션</Term>입니다.

<Sim name="injection" />

보드는 네 겹으로 막습니다. ① 문서는 자료일 뿐이라고 AI에게 일러 둔다 ② AI가 수상한 문장을 스스로 표시한다 ③ 서버 코드가 표현과 날짜 범위를 한 번 더 검사한다 ④ **사람이 원문과 대조한 뒤 저장한다.** 어느 한 겹도 완벽하지 않아서 겹칩니다.

## 시연

<Steps>
<FdStep>

**3회차 보드와 4회차 보드를 나란히.** `교사 로그인` 줄이 새로 생겼고, 로그인하면 **평가 등록** 폼과 **평가계획 문서로 등록** 상자가 나타납니다.

</FdStep>
<FdStep>

**Supabase 화면 네 곳.** 프로젝트를 만드는 **New project**, SQL을 붙여 넣고 **Run**을 누르는 **SQL Editor**, 표를 엑셀처럼 보는 **Table Editor**, 주소와 공개 키를 복사하는 **Connect**(또는 **Settings → API Keys**)입니다.

</FdStep>
<FdStep>

**Claude Console 두 곳과 숨은 지시문.** [Spend limits](https://platform.claude.com/settings/spend-limits)에서 한도를 먼저 걸고 [API keys](https://platform.claude.com/settings/keys)에서 키를 만듭니다. 그다음 숨은 지시문이 든 문서를 넣어 빨간 경고가 뜨는 것을 봅니다.

</FdStep>
</Steps>

메뉴는 자주 바뀝니다. 이름이 다르게 보이면 [Supabase API 키 안내](https://supabase.com/docs/guides/api/api-keys), [Claude API 키 발급](https://platform.claude.com/docs/en/get-api-key), [사용 한도](https://platform.claude.com/docs/en/api/rate-limits#spend-limits) 문서를 확인하세요.

## 학교에서 AI와 데이터를 다루는 기준

오늘 보드에는 개인정보가 없었습니다. 일부러 그런 주제를 골랐습니다. 실제 업무는 다르므로, 도구를 만들기 전에 여섯 가지를 먼저 정합니다.

**하나. 무엇을 넣어도 되는지 나눈다.**

| 넣어도 되는 것 | 가명 처리하고 지침을 확인한 뒤에 | 넣지 않는 것 |
| --- | --- | --- |
| 학사일정, 공개된 평가계획, 양식, 내가 만든 수업 자료 | 점수 분포 분석, 설문 응답 묶기, 제출 여부 집계 | 학생 실명·학번·연락처·주소 |
| 개인을 알 수 없는 집계 숫자 | (이름과 학번을 임의 코드로 바꾼 사본으로) | 성적 원본, 상담 기록, 건강·가정 정보 |
| 가상 데이터 | | 나이스에서 내려받은 원본 파일 |

가운데 칸도 소속 학교와 교육청 지침이 허용할 때만입니다. 계정 종류도 확인하세요. 개인용 계정은 대화를 모델 학습에 쓰도록 허용할지를 설정에서 고르고, Team·Enterprise·API는 기본적으로 학습에 쓰지 않습니다 ([데이터 사용 안내](https://code.claude.com/docs/en/data-usage)).

**둘. <Term id="pseudonymize">가명 처리</Term>는 이렇게 한다.** 사본을 만들어 이름과 학번 열을 임의 코드(S01, S02 …)로 바꿉니다. 번호 순서대로 붙이지 않습니다. 코드와 이름의 대응표는 내 PC에만 두고 AI에게 주지 않습니다. 인원이 적으면 내용만으로 누구인지 드러나니 서술형 칸도 살핍니다. 연습은 [깊이 파기 4.5](/sessions/self-4#5단계-개인정보-점검과-2부-준비)에 있습니다.

**셋. 학생·학부모가 입력하는 앱은 따로 본다.** 동아리 신청이나 상담 예약처럼 이름을 받는 앱은 <Term id="personal-info">개인정보</Term>를 모으는 일입니다. 꼭 필요한 항목만 받고, 누가 볼 수 있는지 RLS로 좁히고, 언제 지울지 정하고, 만들기 전에 학교 개인정보 보호 담당자와 동의 절차를 협의합니다. 개인정보 보호법과 소속 교육청·학교 지침을 따릅니다. 이 과정에서는 가상 데이터로만 연습합니다.

**넷. AI 결과는 초안이다.** 평가와 기록의 최종 판단은 교사가 합니다. 오늘 보드가 자동 등록을 하지 않은 것과 같은 원칙입니다.

**다섯. 학생의 AI 사용은 교육청 지침을 따른다.** 교육부는 2025년 12월 시·도교육청과 함께 "수행평가 시 인공지능(AI) 활용 관리 방안"을 내놓았습니다 ([교육부 보도자료](https://www.moe.go.kr/boardCnts/viewRenew.do?boardID=294&boardSeq=104984&lev=0&searchType=null&statusYN=W&page=1&s=moe&m=020402&opType=N)). 일률적으로 금지하기보다 안전하고 교육적으로 쓰게 한다는 방향이며, 다섯 영역으로 관리합니다. AI 활용 범위 설정, 활용 과정 표기 지도, 학생 유의 사항 안내와 사전교육, 평가 설계 방향, 개인정보보호입니다. 교육청이 이를 2026학년도 학업성적관리 시행지침에 반영하기로 했으니, 실제 기준은 소속 교육청 지침과 우리 학교 학업성적관리규정에서 확인하세요.

**여섯. 계속 운영할지 판단한다.**

| 질문 | 예 | 아니오 |
| --- | --- | --- |
| 나 혼자 또는 몇 사람만 쓰나 | 지금처럼 쓴다 | 계정 관리가 필요하다 |
| 개인정보가 없나 | 지금처럼 쓴다 | 개인정보 보호 담당자와 협의한다 |
| 멈춰도 업무가 돌아가나 | 지금처럼 쓴다 | 무료 요금제로는 부족하다 |
| 내가 자리를 비워도 누가 고칠 수 있나 | 지금처럼 쓴다 | 저장소와 계정을 넘겨받을 사람을 정한다 |

"아니오"가 하나라도 있으면 학교의 정식 서비스로 볼 일입니다. 정보부, 행정실과 먼저 상의하세요.
