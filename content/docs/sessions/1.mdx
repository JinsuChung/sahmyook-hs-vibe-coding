## 개념

### 바이브 코딩의 탄생

2025년 2월 2일, OpenAI 공동창업자 **안드레이 카파시**가 X(옛 트위터)에 새로운 코딩 방식을 소개했습니다. 코드가 있다는 사실조차 잊고 "분위기(vibe)에 몸을 맡기는" 코딩, 바로 <b><Term id="vibe-coding">바이브 코딩</Term></b>입니다 ([원문](https://x.com/karpathy/status/1886192184808149383)). 이 말은 그해 콜린스 사전 <b>올해의 단어(2025)</b>로 뽑혔습니다 ([Wikipedia](https://en.wikipedia.org/wiki/Vibe_coding)).

뜻은 간단합니다. **코드를 모르는 사람도 말로 설명해서 소프트웨어를 만들 수 있게 됐다**는 것입니다.

<Analogy title="학교 업무에 빗대면">
  예전에는 학교에 프로그램 하나를 들이려면 예산 요구 → 업체 선정 → 납품까지 한 학기가 걸렸습니다. 이제는 학생에게 과제를 안내하듯 말로 설명하면 몇 분 안에 동작하는 도구가 나옵니다.
</Analogy>

### 그런데 바이브만으로는 사고가 난다

"알아서 해줘"로만 맡기면 문제가 생깁니다. 실제로 있었던 일입니다.

| 시기 | 사건 | 교훈 |
| --- | --- | --- |
| 2025년 5월 | 한 바이브 코딩 플랫폼으로 만든 웹앱 1,645개 가운데 170개에서 개인정보가 드러날 수 있는 취약점 발견 | 만든 뒤 **보안 점검**을 건너뛰었다 |
| 2025년 7월 | 한 AI 코딩 서비스의 에이전트가 "아무것도 바꾸지 말라"는 지시에도 운영 중인 데이터베이스를 삭제 | AI에게 **되돌릴 수 없는 권한**을 줬다 |

출처: [Wikipedia — Vibe coding](https://en.wikipedia.org/wiki/Vibe_coding)

그 앱에 학생 명단이 들어 있었다면 어땠을까요. 만드는 것은 AI가 해도, **무엇을 만들지 정하고 결과를 확인하는 것은 사람의 몫**입니다.

### 에이전틱 엔지니어링

카파시는 2026년 4월 세콰이아 어센트에서 이렇게 정리했습니다. "바이브 코딩은 바닥을 올리고, 에이전틱 엔지니어링은 천장을 올린다" ([요약 기사](https://www.aibuilderclub.com/blog/karpathy-agentic-engineering)).

<b><Term id="agentic-engineering">에이전틱 엔지니어링</Term></b>은 AI <Term id="agent">에이전트</Term>가 계획·작성·시험을 하고, 사람은 **무엇을 만들지 정하기 → 계획 검토 → 결과 검증**을 맡는 일하는 방식입니다.

| 구분 | 바이브 코딩 | 에이전틱 엔지니어링 |
| --- | --- | --- |
| 태도 | "알아서 해줘" | "이렇게 해줘, 그리고 내가 확인할게" |
| 시작 | 바로 만들기 | 계획 먼저 보기 (플랜 모드) |
| 안전장치 | 없음 | 권한 승인, 검증 기준, 버전 관리(Git) |
| 어울리는 일 | 나만 쓰는 일회용 도구 | 동료가 쓰는 도구, 학생이 쓰는 서비스 |

<Callout type="info" title="교사 관점으로 번역하면">
  선생님이 이미 날마다 하는 일입니다. <b>수업 설계</b>(무엇을 왜 가르칠지 정하기), <b>과제 안내</b>(무엇을 어떻게 해 올지 분명하게 지시하기), <b>채점과 피드백</b>(결과를 기준에 비춰 확인하기). 이 세 가지가 곧 AI에게 일을 시키는 역량입니다. 이 과정의 1–2회차는 바이브 코딩으로 가볍게 시작하고, 3회차부터 에이전틱 엔지니어링의 안전장치를 하나씩 더해 갑니다.
</Callout>

### 인스턴트 소프트웨어의 시대

벤처캐피털 a16z의 아니시 아차르야는 2025년 8월 이렇게 썼습니다. 소프트웨어를 만들지 말지는 그동안 **투자 대비 효과**가 정했지만, 이제는 **상상력**만이 한계라고요 ([Disposable Software](https://a16z.com/disposable-software/)).

<Term id="instant-software">인스턴트 소프트웨어</Term>는 필요할 때 말로 만들어 쓰고, 필요 없으면 지우는 작은 도구입니다. 6개 반 점수 파일 모으기, 제출물 파일 이름 맞추기, 글자 수 세기. 모두 "프로그램까지 만들 일은 아니던" 일입니다. 이제는 10분이면 만들고, 다 쓰면 지워도 됩니다.

### 학교 업무로 보면

**일반적인 고등학교 업무 분장**을 기준으로, 부서마다 있을 법한 반복 업무와 이 과정에서 만들어 볼 것을 짝지었습니다. 특정 학교의 내부 사정이 아니라 어느 학교에나 있을 만한 일을 골랐으니, 우리 학교 부서 이름과 달라도 비슷한 일을 찾아보세요. 이 표가 여덟 회차 전체의 지도입니다.

| 부서 | 이런 반복 업무가 있다면 | 만들어 볼 것 | 회차 |
| --- | --- | --- | --- |
| 교무기획부 | 학사일정 안내, 가정통신문, 교직원 회의록 | 가정통신문 초안 → 가정통신문 스킬, 월요일 주간 업무 브리핑 | 1.5, 5, 7 |
| 교육연구부 | 반별 수행평가 점수 취합·검산, 평가 일정 모으기 | 점수 취합기, 수행평가 일정 보드(웹앱) | 2, 3–4 |
| 학생생활안전부 | 출결·생활지도 현황 집계, 당번표 | 출결 통계와 현황 집계표 | 2.5 |
| 진로진학상담부 | 진로 체험 신청 현황, 진로 탐색 지도 | 신청·설문 응답 집계, 진로 탐색 질문 도우미 | 2.5, 8 |
| 창의인성부 | 동아리 신청·발표회, 행사 사진 정리 | 행사 사진 날짜별 정리, 동아리 소개 페이지 | 1, 3.5 |
| 교육정보부 | 기자재 목록 관리, 정보보안 자체점검 | 기자재 목록 정리, 학교 AI 도구 운영 기준 | 1, 8 |
| 학년부·담임 | 제출물 확인, 학급 안내, 생기부 초안 점검 | 미제출자 찾기, 글자 수·바이트 계산기, 생기부 문구 점검 스킬 | 2, 6 |
| 교과 교사 | 수업 자료, 학생 질문 응대 | 답 대신 질문하는 과목 학습 도우미 | 8 |
| 모든 부서 | 받은 공문의 제출 기한 챙기기 | 공문 제출 기한 일정표 → 공문 요약 스킬 → 공문함 자동 정리 | 1, 5, 7 |

1부(1–4회차)에서는 표의 **도구**를 만들고, 2부(5–8회차)에서는 그 일을 맡아서 하는 **에이전트**를 길러 냅니다. 오늘 실습에 쓰는 "정리 안 된 교무실 공유폴더"에도 이 부서들의 파일 42개가 뒤섞여 있습니다. 학교·기관·인물·숫자는 모두 가상입니다.

### 챗봇과 에이전트는 무엇이 다른가

| | <Term id="chatbot">챗봇</Term> (웹 채팅) | 에이전트 (<Term id="claude-code">Claude Code</Term>) |
| --- | --- | --- |
| 파일 | 내가 올리고, 답을 복사해 내가 저장 | **내 컴퓨터 폴더를 직접 열어 읽고 씀** |
| 실행 | 내가 직접 | 프로그램을 실행하고 결과를 확인 |
| 반복 | 틀리면 내가 다시 질문 | 스스로 확인하고 고침 |
| 사람의 역할 | 손발 | **지시하고 승인하기** |

아래에서 같은 일을 두 방식으로 시켜 보세요.

<Sim name="chat-vs-agent" />

에이전트는 파일을 고치거나 명령을 실행하기 전에 **<Term id="permission">권한</Term>을 묻습니다.** 이 승인 버튼이 첫 번째 안전장치입니다. 플랜 모드를 고르면 계획을 내놓을 때까지 파일을 고치지 않습니다.

<Sim name="agent-loop" />

  Anthropic의 법무팀과 마케팅팀은 개발자 없이 업무 도구를 직접 만들어 씁니다. 파일을 옮기고, 바꾸고, 한꺼번에 분석하는 일이 비개발자에게 가장 쓸모 있는 영역입니다 ([How Anthropic teams use Claude Code](https://claude.com/blog/how-anthropic-teams-use-claude-code)).
</Callout>

### 왜 Claude Code로 배우나요

한 문장으로 답하면 이렇습니다. **생각을 정리하는 대화, 기획 문서, 프로그램 만들기가 한 대화 안에서 끊기지 않고, 내 PC의 업무 파일을 직접 다루기** 때문입니다.

| 순서 | 내가 하는 말 (예) | 하는 일 | 남는 것 |
| --- | --- | --- | --- |
| 1 | "반별 수행평가 점수를 모으는 데 매번 한 시간이 걸려. 같이 생각해 보자" | 채팅 | 대화 |
| 2 | "필요한 걸 나한테 질문해서 기획서로 정리해줘" | 기획 문서 | `기획서.md` |
| 3 | "기획서대로 6개 반 점수 파일을 하나로 모으는 도구를 만들어줘" | 코드 | 도구 파일 |
| 4 | "실습 자료로 돌려 보고 합계가 원본과 맞는지 표로 보여줘" | 실행·검증 | 결과 파일, 검산표 |
| 5 | "교과협의회에 낼 한 장 요약을 써줘" | 문서 | `요약.md` |

오늘은 1번, 2회차는 2–4번을 연습하고, 3–4회차는 이것을 웹·데이터·AI로 넓힙니다. 5회차부터는 같은 도구로 에이전트를 만듭니다. 터미널(검은 명령 창) 없이 데스크톱 앱에서 시작할 수 있다는 점도 고른 이유입니다.

<DeepDive title="다른 AI 도구와는 무엇이 다른가요">

AI 도구는 크게 네 종류입니다. 모두 좋은 도구이고 기능이 빠르게 늘고 있어서, 아래는 **일반적인 특징**입니다.

| 구분 | 웹 채팅 (ChatGPT, Gemini, Claude 웹 등) | 앱 빌더 (Lovable, Replit, Bolt 등) | 개발자 편집기 (Cursor, GitHub Copilot 등) | Claude Code |
| --- | --- | --- | --- | --- |
| 내 PC 파일 다루기 | 올린 파일만 | 주로 클라우드 안에서 | 코드 폴더 중심 | 업무 폴더 전체 (엑셀·PDF·워드·사진) |
| 웹앱이 아닌 작은 도구 (엑셀 취합, 파일 정리) | 방법을 알려 줌 | 웹앱 위주 | 가능 | 직접 만들고 실행해서 확인 |
| 시작 장벽 | 가장 낮음 | 낮음 | 개발 지식 필요 | 낮음 (데스크톱 앱) |

내 PC에서 일하는 에이전트로는 OpenAI Codex, Google Gemini CLI 등도 있습니다. 개념이 같아서 이 과정에서 익힌 일하는 방식은 다른 도구에서도 통합니다.

학교에 빗대면 웹 채팅은 **전화 상담**, 앱 빌더는 **누리집 제작 업체**, 개발자 편집기는 **전산실 전용 장비**이고, Claude Code는 **옆자리에 앉은 일 잘하는 신규 선생님**에 가깝습니다. 문서도 쓰고 엑셀도 합치고 프로그램도 만들되, 중요한 일은 결재를 받고 합니다.

</DeepDive>

<DeepDive title="문서도 코드도 잘하는가: 공개 순위로 본 근거 (2026-11-16 확인)">

기획서는 잘 쓰는데 코드가 약하거나, 코드는 잘 짜는데 문서가 어색하면 둘 사이를 사람이 다시 옮겨 적어야 합니다. 그래서 **같은 AI가 둘 다 잘하는지**를 공개 순위로 확인해 두었습니다.

| 영역 | 어디서 재나 | 2026-11-16에 확인한 결과 |
| --- | --- | --- |
| 코드 고치기 | [Vals.ai SWE-bench Verified](https://www.vals.ai/benchmarks/swebench) — 실제 오픈소스 프로젝트의 문제 500개를 고치게 하고 시험으로 채점 | 1위 Claude Opus 5 97.0%, 2위 96.4%, 3위 96.2% (표의 마지막 갱신일 2026-09-01. 그 뒤에 나온 모델은 아직 표에 없음) |
| 웹 개발 | [Arena WebDev](https://arena.ai/leaderboard/webdev) — 사람들이 두 AI의 결과물을 직접 비교해 투표 | 1–3위가 Claude Fable 5.2, Claude Opus 5.5, Claude Sonnet 5.5 (2026-11-13 표) |
| 글쓰기·대화 종합 | [Arena Text](https://arena.ai/leaderboard/text) — 같은 방식의 투표 | 1–2위는 Google의 Gemini 4 계열, 3위 Meta의 Muse Wonder, 4위 Claude Opus 5.5, 5위 Claude Fable 5. 다섯 모델이 약 20점 안에 모여 있음 (2026-11-11 표) |

숫자는 이렇게 읽으면 됩니다. 상위 모델끼리의 차이는 근소하고, 순위는 새 모델이 나올 때마다 바뀝니다. 글쓰기 종합 순위처럼 다른 회사 모델이 앞서는 영역도 있습니다. 이 과정이 Claude Code를 고른 이유는 점수 하나가 아니라, **최상위권의 문서 능력과 코드 능력을 한 도구, 한 대화 안에서 함께 쓸 수 있다**는 점입니다.

솔직한 한계도 있습니다. **유료 플랜**이 필요하고, 대화 내용이 AI 모델로 **전송**되며, 결과는 언제나 **사람이 검증**해야 합니다. 그래서 다음 약속이 필요합니다.

</DeepDive>

### 이 과정의 약속 세 가지

여덟 회차 내내 지킬 약속입니다. 실습을 시작하기 전에 먼저 정해 둡니다.

| 약속 | 왜 그런가 |
| --- | --- |
| **1. 실습은 가상 데이터로만 한다** | 실습 자료는 모두 가상의 "새봄고등학교" 것입니다. 연습하다 생긴 실수가 실제 업무에 닿지 않습니다. |
| **2. 학생 정보는 AI에 넣지 않는다** | 내가 쓴 말과 Claude Code가 읽은 파일 내용은 처리를 위해 Anthropic의 AI 모델로 **전송**됩니다. 학생의 이름·학번·성적·상담 내용·건강·가정 정보는 보호해야 할 개인정보이고, 한번 나간 정보는 되돌릴 수 없습니다. 나이스(NEIS)에서 내려받은 원본 파일도 쓰지 않습니다. |
| **3. 평가와 기록의 최종 판단은 교사가 한다** | AI는 초안·점검·취합을 돕는 보조입니다. 성적과 학교생활기록부의 책임은 교사에게 있고, 그 근거는 교사가 직접 관찰한 학생의 활동이어야 합니다. |

<DeepDive title="내 대화는 AI 학습에 쓰이나요">

계정 종류에 따라 다릅니다. 개인용 계정(Free·Pro·Max·Ultra)은 내 데이터를 모델 개선에 쓰도록 허용할지를 **설정에서 스스로 고릅니다**([개인정보 설정](https://claude.ai/settings/data-privacy-controls)). 허용하면 보관 기간은 5년, 허용하지 않으면 30일입니다. Team·Enterprise 플랜과 API는 기본적으로 모델 학습에 쓰지 않습니다. 출처: [Claude Code 공식 문서 — Data usage](https://code.claude.com/docs/en/data-usage)

학습에 쓰지 않도록 꺼 두어도 **전송 자체는 일어납니다.** 그래서 설정과 상관없이 원칙은 하나입니다. 학생 정보는 넣지 않습니다. 꼭 필요한 업무는 가명 처리와 학교·교육청 지침을 먼저 확인하며, 그 방법은 4회차에서 다룹니다.

</DeepDive>
