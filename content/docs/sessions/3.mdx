## 개념

`평가계획서_최종.hwp`, `평가계획서_최종_수정.hwp`, `평가계획서_진짜최종_v3.hwp`. 이런 파일 이름을 만들어 본 적이 있다면 오늘 배울 것의 절반은 이미 이해하신 것입니다. 나머지 절반은 2회차가 남긴 문제에서 나옵니다. 내가 만든 도구는 **내 PC에서만** 열립니다. 옆자리 선생님께 드리려면 파일을 보내야 하고, 고칠 때마다 다시 보내야 합니다.

오늘은 이 두 문제를 차례로 풉니다. 먼저 안전망(Git)을 치고, 그 위에서 링크로 나눕니다(배포).

### Git은 되돌릴 수 있는 세이브 포인트

AI는 한 번에 여러 파일을 빠르게 고칩니다. 잘되던 기능이 다음 요청 때문에 깨지는 일이 흔합니다. Claude Code에도 되돌리기(`/rewind`)가 있지만, 공식 문서는 이것이 버전 관리를 대신하지 않는다고 밝힙니다([Checkpointing](https://code.claude.com/docs/en/checkpointing#not-a-replacement-for-version-control)). 되돌리기는 Claude가 파일 편집 도구로 고친 파일만 기억해서, 명령으로 옮기거나 이름을 바꾸거나 지운 파일은 돌아오지 않습니다. 그 대화 안에서의 빠른 복구용인 셈입니다. 무엇이 어떻게 바뀌었든 되돌릴 수 있는 진짜 안전망, 그리고 다른 PC·동료와의 공유는 <Term id="git">Git</Term>이 맡습니다.

알아야 할 말은 네 개뿐입니다.

| 개념 | 뜻 | 학교에 빗대면 |
| --- | --- | --- |
| <Term id="repository">저장소</Term> | 변경 이력이 함께 기록되는 폴더 | 수정 이력이 붙어 있는 문서철 |
| <Term id="commit">커밋</Term> | 지금 상태를 한 줄 메모와 함께 저장한 세이브 포인트 | 학급 일지의 하루 기록 |
| <Term id="push">푸시</Term> | 내 PC의 이력을 <Term id="github">GitHub</Term>에 올리기 | 교무실 공용 캐비닛에 사본 넣기 |
| <Term id="gitignore">.gitignore</Term> | 기록하지도 올리지도 않을 파일 목록 | 캐비닛에 넣지 않는 서류 목록 |

아래에서 직접 커밋하고, 망가뜨리고, 되살려 보세요.

<Sim name="commit-timeline" />

명령어는 외울 필요가 없습니다. 하고 싶은 것을 말하면 Claude Code가 Git 명령을 대신 실행합니다.

| 하고 싶은 것 | Claude Code에게 하는 말 |
| --- | --- |
| 시작 | `이 폴더를 Git 저장소로 만들고 첫 커밋을 해 줘` |
| 저장 | `지금까지 바뀐 내용을 한글 메시지로 커밋해 줘` |
| 되돌리기 | `방금 커밋한 변경을 되돌려 줘. 이력은 지우지 말고` |
| 올리기 | `GitHub에 비공개 저장소를 만들고 푸시해 줘` |

<Callout type="warn" title="저장소는 비공개로, 학생 자료는 처음부터 빼고">
  GitHub 저장소는 <Term id="private-repo">비공개</Term>(Private)로 만듭니다. 그리고 학생 명단·성적 같은 원본 자료와 비밀번호·키 파일(`.env`)은 첫 커밋 **전에** .gitignore에 넣습니다. 한 번 커밋된 파일은 나중에 지워도 이력에 남기 때문입니다. 4회차부터는 키가 든 파일이 실제로 생깁니다.
</Callout>

<DeepDive title="혼자 쓸 때와 함께 쓸 때">

오늘은 혼자 쓰는 Git까지만 합니다. 같은 교과 선생님과 저장소를 함께 고치기 시작하면 <Term id="branch">브랜치</Term>(수정안 사본), <Term id="pull-request">풀 리퀘스트</Term>(협의회에 수정안 올리기), <Term id="merge">머지</Term>(확정본에 반영)가 필요해집니다. 교과협의회에서 평가계획서를 함께 고치는 절차와 똑같습니다. [깊이 파기 3.5의 3단계](/sessions/self-3#3단계-함께-고치는-법)에서 혼자서도 따라 할 수 있게 다룹니다.

</DeepDive>

### 배포는 링크 하나로 동료에게 가는 길

2회차의 계산기는 파일을 더블클릭해서 엽니다. 웹앱은 조금 다릅니다. 만드는 동안에는 내 PC에서 띄워 <Term id="localhost">localhost</Term>라는 주소로 보고, 다 되면 인터넷의 서버에 올립니다. 이것이 <Term id="deploy">배포</Term>입니다.

| | localhost (내 PC) | 배포 주소 (`….vercel.app`) |
| --- | --- | --- |
| 누가 여나 | 나만 | 주소를 아는 누구나 |
| 언제 바뀌나 | 파일을 저장하는 즉시 | 푸시하고 1–2분 뒤 |
| 쓰임 | 고치면서 확인 | 동료·학생과 공유, 휴대폰에서 열기 |
| 꺼지면 | 내 PC를 끄면 닫힘 | 늘 열려 있음 |

<Term id="vercel">Vercel</Term>은 GitHub 저장소를 연결해 두면 **푸시할 때마다 자동으로 다시 배포**합니다. 앞에서 배운 커밋과 푸시가 그대로 "업데이트" 버튼이 됩니다.

<Sim name="deploy-pipeline" />

새로 나오는 말은 셋입니다. <Term id="nextjs">Next.js</Term>는 웹앱의 뼈대이고 구조는 Claude가 잡습니다. <Term id="nodejs">Node.js</Term>는 그 웹앱을 내 PC에서 띄우는 프로그램입니다. <Term id="build">빌드</Term>는 배포 직전의 최종 교정으로, 코드에 오류가 있으면 여기서 멈추고 이유를 알려 줍니다.

<Callout type="warn" title="배포 주소는 주소를 아는 누구나 열 수 있습니다">
  오늘 배포할 수행평가 일정 보드에는 평가명·과목·학년·마감일·담당 교사만 있습니다. 학생 이름도 점수도 없어서 공개 주소여도 괜찮은 주제입니다. 반대로 **학생 정보가 든 것은 배포하지 않습니다.** "주소를 우리 반에만 알려 주면 된다"는 안전장치가 아닙니다. 주소는 쉽게 퍼집니다.
</Callout>

Vercel의 무료(Hobby) 요금제는 <Fact k="vercel.hobby" />로 연수와 시제품에는 넉넉합니다. 다만 용도 조건(<Fact k="vercel.hobby.use" />)이 붙어 있으니, 학교의 정식 서비스로 운영하려면 [요금제 안내](https://vercel.com/docs/plans/hobby)와 약관을 확인하고 학교와 상의하세요.

<Steps>
<FdStep>

**망가뜨리고 되살리기.** 강사가 글자 수 계산기의 배경을 형광 분홍으로, 글자를 3배로 바꿔 커밋한 뒤 "방금 커밋한 변경을 되돌려 줘" 한마디로 되살립니다.

</FdStep>
<FdStep>

**푸시하면 휴대폰 화면이 바뀐다.** 미리 배포해 둔 보드의 제목을 바꿔 푸시하고, 1분쯤 뒤 수강생 휴대폰에서 새로 고쳐 확인합니다.

</FdStep>
<FdStep>

**빌드 에러는 단서다.** `data/assessments.ts`에서 쉼표 하나를 지우고 푸시해 일부러 빌드를 실패시킨 다음, Vercel의 빨간 에러 로그를 Claude Code에 붙여 넣어 고칩니다.

</FdStep>
</Steps>
