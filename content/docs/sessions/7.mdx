## 개념

### 시키면 하는 에이전트에서 때가 되면 하는 에이전트로

5–6회차의 에이전트는 내가 불러야 일했습니다. `/doc-digest`를 입력하거나 "가정통신문 초안 써 줘"라고 말해야 움직였습니다. 이번 회차에는 사람이 부르던 자리에 시계를 둡니다. <Term id="scheduled-task">예약 작업</Term>은 정해 둔 시간이 되면 **새 세션**을 열고, 저장해 둔 지시문을 받아 그대로 일합니다.

| | 대화로 시킬 때 (5–6회차) | 예약으로 돌릴 때 (7회차) |
| - | - | - |
| 시작 | 내가 말할 때 | 정해 둔 시간 |
| 지켜보는 사람 | 있다. 승인 창을 읽고 누른다 | 없다. 물어도 답할 사람이 없다 |
| 앞의 대화 | 이어서 말할 수 있다 | 매번 새 세션. 지시문과 CLAUDE.md, 폴더의 파일이 전부다 |
| 잘못됐을 때 | 그 자리에서 고친다 | 기록을 보고 나중에 안다 |

표의 오른쪽 칸이 이 회차에서 할 일을 정해 줍니다. 지시문은 혼자 읽어도 일을 끝낼 수 있게 쓰고, 하면 안 되는 일을 미리 적고, 기록을 남기게 합니다.

<Analogy title="학교로 비유하면: 당번표와 점검표">
  문단속 당번은 정해진 시간에 정해진 곳을 돌고 점검표에 표시합니다. 창문이 깨져 있으면 직접 고치지 않고 적어 두었다가 담임에게 알립니다. 예약 작업도 같습니다. 정해진 시간에 정해진 일만 하고, 기록을 남기고, 판단이 필요한 일은 사람에게 넘깁니다.
</Analogy>

### 어디서 돌릴 것인가

Claude Code에서 일을 예약하는 방법은 세 가지입니다([공식 문서의 비교표](https://code.claude.com/docs/en/desktop-scheduled-tasks#compare-scheduling-options)를 학교 말로 옮겼습니다).

| | 데스크톱(로컬) 예약 작업 | <Term id="cloud-task">클라우드 예약 작업</Term> | <Term id="loop-command">`/loop`</Term> |
| - | - | - | - |
| 어디서 도나 | 내 PC | Anthropic 클라우드 | 내 PC의 지금 세션 |
| PC가 꺼져 있으면 | 돌지 못한다 | 돈다 | 돌지 못한다 |
| 내 PC의 폴더 | 읽고 쓴다 | 보지 못한다. 실행할 때마다 GitHub 저장소를 새로 복제해서 일한다 | 읽고 쓴다 |
| 언제까지 | 끌 때까지 | 끌 때까지 | 세션이 열려 있는 동안. 반복 작업은 7일 뒤 자동 종료 |
| 학교 일로 치면 | 교무수첩 폴더로 만드는 월요일 브리핑 | GitHub에 올려 둔 수행평가 일정 보드의 주말 점검 | "배포가 끝났는지 5분마다 봐 줘" |

질문 세 개에 답하면 어느 쪽이 맞는지 알려 주는 도구입니다. 아래 학교 예시를 눌러 보세요.

<Sim name="schedule-picker" />

주간 브리핑은 교무수첩 폴더의 학사일정과 공문을 읽어야 하므로 **데스크톱(로컬) 예약 작업**이 맞습니다. 대신 알아 둘 조건이 있습니다([문서](https://code.claude.com/docs/en/desktop-scheduled-tasks#how-scheduled-tasks-run)).

- **앱이 열려 있고 PC가 깨어 있을 때만 실행됩니다.** PC가 잠든 사이에 예약 시각이 지나가면 그 실행은 건너뜁니다.
- 놓친 실행은 앱을 열거나 PC가 깨어날 때 **지난 7일 치 가운데 가장 최근 것 한 번만** 대신 돌립니다(<Term id="catch-up-run">따라잡기 실행</Term>). 월요일 8시 브리핑이 화요일 오후에 돌 수 있다는 뜻입니다. 그래서 지시문에 "월요일이 아니면 이번 주 월요일을 기준일로 삼는다"를 넣어 둡니다.
- 예약한 시각보다 몇 분 늦게 시작하는 것은 정상입니다. 요청이 한꺼번에 몰리지 않게 작업마다 정해진 지연을 둡니다.

<DeepDive title="클라우드 예약 작업과 /loop는 언제 쓰나">

**클라우드 예약 작업**은 예전에 루틴(routine)이라고 부르던 기능입니다. Anthropic이 관리하는 클라우드에서 돌기 때문에 PC가 꺼져 있어도 실행되지만, 실행할 때마다 지정한 GitHub 저장소를 새로 복제해 그 안에서 일합니다. 내 PC의 교무수첩 폴더에는 닿지 못합니다. 지금은 연구 미리보기 단계라 동작이 바뀔 수 있고, 가장 짧은 간격은 1시간입니다([문서](https://code.claude.com/docs/en/routines)). 3회차에 GitHub에 올려 둔, 개인정보가 없는 자료를 다룰 때 후보가 됩니다.

**`/loop`**는 세션 안에서 쓰는 가벼운 반복입니다. 터미널의 Claude Code에서 `/loop 5m 배포가 끝났는지 확인해 줘`처럼 쓰면 세션이 열려 있는 동안 5분마다 같은 지시를 되풀이합니다. 세션을 닫으면 멈추고, 놓친 실행을 따라잡지도 않습니다([문서](https://code.claude.com/docs/en/scheduled-tasks)).

세 방식을 사례로 가려 보는 연습은 [깊이 파기 7.5의 1단계](/sessions/self-7#1단계-어디서-돌릴-것인가)에 있습니다.

</DeepDive>

### 자동화의 안전 설계 여섯 가지

이 회차의 핵심입니다. 대화에서는 승인 창이 나를 멈춰 세웠지만, 예약 실행에는 지켜보는 사람이 없습니다. 그러니 멈출 자리를 **미리 설계해** 두어야 합니다.

| 원칙 | 주간 브리핑에서는 |
| - | - |
| (가) 읽기 위주로, 쓰기는 정해진 곳에만 | 새로 만드는 파일은 `보낸문서/주간브리핑_〈기준일〉.md` 하나뿐. 나머지는 읽기만 |
| (나) 지우기·보내기·덮어쓰기는 자동으로 하지 않는다 | 파일을 지우거나 옮기거나 이름을 바꾸지 않는다. 메일, 메신저, 웹 업로드를 하지 않는다 |
| (다) <Term id="human-in-the-loop">사람이 확인하는 지점</Term>을 정한다 | 브리핑은 내가 읽는 초안이다. 판단이 필요한 것은 "확인이 필요한 것"에 모으고, 제출과 발송은 사람이 한다 |
| (라) <Term id="run-log">실행 기록</Term>을 남기고 읽는다 | 파일 끝에 "실행 메모"(읽은 파일, 읽지 못한 파일, 하지 못한 일)를 붙인다 |
| (마) <Term id="idempotent">두 번 돌려도 문제가 없게</Term> | 같은 기준일의 브리핑이 이미 있으면 "이미 있음"만 답하고 끝낸다 |
| (바) 학생 정보가 있는 폴더는 대상에서 뺀다 | 읽을 곳을 지시문에 적는다. 학생 정보는 옮겨 적지 않는다 |

<Callout type="warn" title="예약 작업이 여는 폴더에 실제 학생 정보를 두지 마세요">
  예약 작업은 지정한 폴더의 파일을 사람의 확인 없이 읽습니다. 실제 학생의 이름, 성적, 상담 기록, 나이스에서 내려받은 원본이 든 폴더는 예약 작업의 작업 폴더로 지정하지 않습니다. 실습의 `생기부_초안/`은 가상 자료입니다.
</Callout>

<DeepDive title="지시문은 부탁이고 권한은 잠금장치다">

지시문에 "파일을 지우지 않는다"고 적으면 Claude는 지우려 하지 않습니다. 하지만 공식 문서는 분명히 말합니다. 지시문과 CLAUDE.md는 Claude가 **하려는 일**을 정할 뿐이고, **허용되는 일**은 Claude Code가 권한 규칙으로 따로 지킵니다([문서](https://code.claude.com/docs/en/permissions#manage-permissions)).

그래서 자동화는 두 겹으로 설계합니다.

| 겹 | 무엇으로 | 이 회차에서 |
| - | - | - |
| 부탁 | 지시문의 "하지 않는 일" 목록 | 실습 7-1에서 씁니다 |
| 잠금장치 | <Term id="permission-mode">권한 모드</Term>와 <Term id="permission-rule">허용·거부 규칙</Term> | 실습 7-2에서 모드를 고르고, 규칙은 깊이 파기 7.5의 3단계에서 겁니다 |

잠금장치가 하나 더 있습니다. <Term id="hook">훅</Term>은 Claude Code가 정해진 시점에 반드시 실행하는 명령입니다. AI의 판단과 상관없이 실행되므로, 예외 없이 지켜야 하는 일(승인을 기다릴 때 알림 받기, 보호할 파일의 편집 막기)에 씁니다([문서](https://code.claude.com/docs/en/hooks-guide)). 수업에서는 이런 장치가 있다는 것만 알아 두고, 깊이 파기 7.5의 4단계에서 하나를 직접 걸어 봅니다.

</DeepDive>

### 자동화하면 안 되는 일

예약할 수 있다는 것과 예약해도 된다는 것은 다릅니다. 아래 세 가지는 초안이나 제안까지만 자동으로 하고, 마지막은 사람이 합니다.

- **평가와 기록의 판단**: 점수를 확정하는 일, 학교생활기록부 문장을 쓰고 입력하는 일
- **학부모·학생에게 가는 발송**: 가정통신문, 문자, 메일
- **되돌릴 수 없는 삭제와 덮어쓰기**

판별표와 내 업무에 적용하는 연습은 [깊이 파기 7.5의 5단계](/sessions/self-7#5단계-자동화하면-안-되는-일)에서 합니다.

<Step id="7-4" title="로컬 예약 작업 만들기">

[공식 문서의 절차](https://code.claude.com/docs/en/desktop-scheduled-tasks#create-a-scheduled-task) 그대로입니다. 화면의 영어 이름을 따라가세요.

1. **Code** 탭의 사이드바에서 **Scheduled**를 누릅니다. 사이드바의 **More** 메뉴 안에 있을 수도 있습니다.
2. **New task**를 누르면 **New scheduled task** 창이 열립니다. **Create with Claude**와 **Set up manually**가 나오면 **Set up manually**를 고릅니다.
3. **Name**에 이름을 적습니다. 이름은 작업의 폴더 이름으로 쓰이므로 `weekly-briefing`처럼 영문 소문자와 하이픈으로 짓고, 다른 작업과 겹치지 않게 합니다.
4. 이름 아래 칸에 지시문을 붙여 넣습니다. `자동화/주간브리핑_지시문.md`의 "지시문" 제목부터 끝까지입니다.
5. **Trigger**는 잠시 두고, 그 아래 **Advanced settings**를 펼쳐 **General** 탭의 **Only on this computer**를 켭니다. 내 PC에서만 도는 로컬 작업이 됩니다.
6. **Local folder**에서 내 `새봄고_교무수첩` 폴더를 고릅니다. 폴더를 골라야 **Create**가 눌립니다.
7. **Trigger**로 돌아가 **Weekly**를 고르고 요일은 월요일, 시각은 출근해서 PC를 켠 뒤로 잡습니다(예: 오전 8시 20분).
8. 지시문 칸의 도구 줄에서 권한 모드를 **Manual**로 고릅니다. 모델은 그대로 둡니다.
9. **Create**를 누릅니다. 폴더를 신뢰할지 물으면 내 폴더가 맞는지 확인하고 신뢰합니다. 작업의 상세 화면이 열립니다.

<Step id="7-5" title="지금 한 번 실행하고 권한 요청 확인하기">

월요일까지 기다리지 않습니다. 상세 화면에서 **Run now**를 눌러 바로 한 번 실행합니다. 권한 모드가 Manual이므로 파일을 저장하거나 명령을 실행하기 직전에 멈춰 승인을 기다립니다. **History** 목록에서 방금 실행을 눌러 그 세션을 열고, 무엇을 하려는지 읽은 뒤 허용합니다.

여기서 권한 모드를 어떻게 둘지 정합니다([문서](https://code.claude.com/docs/en/desktop-scheduled-tasks#permissions-for-scheduled-tasks)).

| 권한 모드 | 월요일 아침에 일어나는 일 | 이럴 때 |
| - | - | - |
| **Manual** | 파일을 저장하기 직전에 멈춰 기다린다. 내가 그 세션을 열어 허용해야 끝난다 | 처음 몇 주. 승인하는 일 자체가 확인 지점이 된다 |
| **Accept edits** | 폴더 안의 파일 편집과 `mkdir`, `touch`, `mv` 같은 기본 파일 명령을 묻지 않고 실행한다. 멈추지 않고 끝까지 돈다 | 지시문을 믿을 만해졌고, 폴더에 학생 정보가 없을 때 |

파일 편집을 "항상 허용(always allow)"으로 답해도 그 세션에만 적용됩니다. 매주 묻지 않게 하려면 상세 화면의 연필 아이콘(**Edit**)에서 작업의 권한 모드를 **Accept edits**로 바꿉니다. 묻지 않는 범위가 넓어지는 만큼 지시문의 "하지 않는 일"이 더 중요해집니다. Auto와 Bypass permissions는 이 실습에서 쓰지 않습니다.

<Step id="7-6" title="실행 기록 열어 보기">

**History**에서 실행 한 줄을 누르면 그 실행의 세션이 열립니다. 대화로 시켰을 때와 똑같이 무엇을 읽고 무엇을 썼는지 볼 수 있습니다. 세 가지를 확인합니다.

1. 읽은 파일이 지시문에 적은 곳뿐인가
2. 새로 쓴 파일이 브리핑 하나뿐인가

<Step id="7-9" title="헤드리스 실행 스크립트 읽기">

터미널에서 `claude -p "지시"`라고 쓰면 대화 창 없이 한 번 실행하고 답을 출력한 뒤 끝납니다. 이것을 <Term id="headless">헤드리스 실행</Term>이라고 합니다([문서](https://code.claude.com/docs/en/headless)). 완성본의 `자동화/run-weekly.ps1`(Windows)과 `run-weekly.sh`(macOS)가 실행하는 명령은 이 한 줄입니다.

```bash
claude -p "자동화/주간브리핑_지시문.md 파일을 읽고, '지시문' 제목 아래에 적힌 대로 수행해 줘. 오늘 날짜는 2026-11-16로 계산해." --permission-mode dontAsk --allowedTools "Edit(보낸문서/**)" --max-turns 40
```

| 부분 | 뜻 |
| - | - |
| `-p` | 대화 창 없이 한 번 실행하고 마지막 답을 출력한다 |
| `--permission-mode dontAsk` | 물어봐야 하는 동작은 묻지 않고 모두 거부한다. 작업 폴더 안의 파일 읽기, 읽기 전용 명령, 미리 허용한 것만 실행된다 |
| `--allowedTools "Edit(보낸문서/**)"` | `보낸문서/` 안에서만 파일을 만들고 고칠 수 있게 허용한다 |
| `--max-turns 40` | 끝없이 도는 일을 막는 상한이다 |

안전 설계의 (가)와 (나)가 명령 한 줄에 들어 있습니다. 읽기는 폴더 안, 쓰기는 `보낸문서/`만, 나머지는 거부입니다. 스크립트는 이 명령을 실행한 뒤 실행 시각과 마지막 답을 `자동화/실행기록.md`에 덧붙입니다.
