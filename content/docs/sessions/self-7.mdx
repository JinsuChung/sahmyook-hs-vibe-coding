## 1단계 어디서 돌릴 것인가

이 단계를 마치면 어떤 일이든 질문 세 개로 돌릴 곳을 고를 수 있습니다.

<DeepDive title="세 방식을 가르는 질문 세 개">

1. **PC가 꺼져 있어도 돌아야 하나?** 그렇다면 클라우드 예약 작업뿐입니다.
2. **내 PC에만 있는 파일이 필요한가?** 그렇다면 데스크톱(로컬) 예약 작업입니다.
3. **지금 대화가 열려 있는 동안만 필요한가?** 그렇다면 `/loop`로 충분합니다.

1번과 2번이 둘 다 "예"이면 맞는 방식이 없습니다. PC를 켜 둘 수 있는 시간으로 옮기거나, 자료를 클라우드가 닿는 곳으로 옮겨야 합니다.

클라우드 예약 작업이 내 PC의 파일을 보지 못하는 까닭은 일하는 방식에 있습니다. 실행할 때마다 지정한 **GitHub 저장소를 새로 복제**해서 그 안에서 일합니다([문서](https://code.claude.com/docs/en/routines)). 3회차에 배운 저장소가 여기서 다시 쓰입니다. 수행평가 일정 보드처럼 공개해도 되는 자료는 클라우드 예약 작업에 잘 맞습니다.

그렇다면 교무수첩 폴더를 GitHub에 올리면 될까요? 기술로는 되지만 권하지 않습니다. 비공개 저장소라도 공문과 업무 자료를 학교 밖 서비스에 올리는 일이므로 학교와 교육청의 지침을 먼저 확인해야 하고, 학생 정보가 든 파일은 올리지 않습니다.

클라우드 예약 작업에 대해 알아 둘 것이 세 가지 더 있습니다. 만들 때 권한 모드를 고르지 않고, 새 세션은 기본적으로 자동 모드(Auto)로 시작합니다. 작업은 내 개인 계정에 속하며, 연결한 GitHub와 커넥터로 한 일은 내 이름으로 남습니다. 그리고 아직 연구 미리보기 단계입니다.

</DeepDive>

오른쪽 두 칸을 손으로 가리고 먼저 답해 보세요.

| 사례 | 맞는 방식 | 까닭 |
| - | - | - |

| 평일 오후, 받은공문 폴더에 새 공문이 있는지 확인 | 로컬 | 위와 같다. 일정은 Weekdays |

| 방금 푸시한 보드의 배포가 끝났는지 5분마다 확인 | `/loop` | 지금 세션에서 잠깐만 필요하다 |

## 2단계 기록을 읽고 고친다

이 단계를 마치면 기록에서 무엇을 볼지 알고, 본 것을 지시문의 문장으로 옮길 수 있습니다.

<DeepDive title="실행 기록은 세 군데에 남는다">

| 어디에 | 무엇이 남나 | 누가 남기나 |
| - | - | - |
| 작업 상세 화면의 **History** | 지난 실행 전부. 건너뛴 실행도 나오고, 줄을 누르면 그 실행의 세션이 열린다 | 데스크톱 앱 |
| 브리핑 파일 끝의 "실행 메모" | 읽은 파일, 읽지 못한 파일, 하지 못한 일 | 에이전트(지시문이 시켜서) |
| `자동화/실행기록.md` | 실행 시각, 기준일, 종료 코드, 마지막 답 | 헤드리스 스크립트(4단계) |

기록에서 볼 것은 네 가지입니다. ① 빠진 주가 없는가 ② 정상으로 끝났는가 ③ 읽지 못한 파일과 하지 못한 일에 무엇이 적혔는가 ④ 저장했다는 파일이 정말 있는가.

흔한 오해가 하나 있습니다. **정상으로 끝났다는 것은 끝까지 돌았다는 뜻이지, 일을 다 했다는 뜻이 아닙니다.** 그래서 ③을 꼭 읽습니다. History에서 건너뛴 실행 위에 마우스를 올리면 까닭이 나옵니다. PC가 잠들어 있었거나, 앞의 실행이 아직 끝나지 않았거나, 다른 예약 작업이 돌고 있었던 경우입니다([문서](https://code.claude.com/docs/en/desktop-scheduled-tasks#manage-scheduled-tasks)).

</DeepDive>

## 3단계 권한과 승인 지점

이 단계를 마치면 내 예약 작업이 무엇을 묻지 않고 할 수 있는지 읽고 좁힐 수 있습니다.

<DeepDive title="권한 모드는 위임전결 규정이다">

<Term id="permission-mode">권한 모드</Term>는 에이전트가 묻지 않고 할 수 있는 일의 범위입니다. 데스크톱 앱에서는 입력창 아래의 모드 칸에서 고르고, 예약 작업은 작업마다 따로 정합니다([문서](https://code.claude.com/docs/en/permission-modes)).

| 모드 | 묻지 않고 하는 일 | 예약 작업에서는 |
| - | - | - |
| **Manual** | 읽기만. 파일을 고치거나 명령을 실행하기 전에 묻는다 | 쓰기 직전에 멈춰 기다린다. 처음 몇 주에 알맞다 |
| **Accept edits** | 읽기, 파일 편집, `mkdir`·`touch`·`mv` 같은 기본 파일 명령 | 멈추지 않는다. 파일을 옮기는 명령도 묻지 않으므로 지시문과 폴더 구성이 중요하다 |
| **Plan** | 읽고 살펴본 뒤 계획만 내놓는다 | 결과 파일을 만들지 않으므로 맞지 않는다 |
| **Auto** | 대부분. 별도의 분류기 모델이 동작을 대신 검토한다 | 이 과정에서는 쓰지 않는다 |
| **Bypass permissions** | 거의 전부 | 쓰지 않는다. 문서도 격리된 환경에서만 쓰라고 한다 |

예약 작업에서 권한이 특히 중요한 까닭은 답할 사람이 없기 때문입니다. 승인이 필요한 동작을 만나면 실행은 그 자리에서 멈춰 기다립니다. 그래서 문서는 만든 직후 **Run now**로 돌려 어떤 요청이 뜨는지 보고, 매번 필요한 것만 항상 허용해 두라고 권합니다. 허용해 둔 것은 상세 화면의 **Always allowed** 패널에서 보고 거둘 수 있습니다.

</DeepDive>

<DeepDive title="허용할 것만 허용한다: 규칙 세 종류">

모드가 큰 틀이라면 <Term id="permission-rule">규칙</Term>은 예외 조항입니다. 허용(allow), 물어보기(ask), 거부(deny) 세 종류가 있고 **거부가 가장 먼저** 적용됩니다. 거부 규칙은 어느 모드에서나 막습니다([문서](https://code.claude.com/docs/en/permissions)). 폴더의 `.claude/settings.json`에 이렇게 적습니다.

```json
{
  "permissions": {
    "deny": ["Read(./비공개_연습/**)", "Bash(rm *)"]
  }
}
```

첫 규칙은 `비공개_연습` 폴더 아래의 파일을 읽지도 고치지도 못하게 하고, 둘째 규칙은 `rm`으로 시작하는 삭제 명령을 막습니다. 다만 완벽한 벽은 아닙니다. 문서에 따르면 읽기 거부 규칙은 Claude의 파일 도구와 `cat` 같은 알려진 명령에 적용되고, 스크립트가 파일을 직접 여는 경우까지 막지는 못합니다. 명령 규칙도 다르게 쓴 명령은 놓칠 수 있습니다. 그래서 순서는 이렇습니다. 실제 학생 정보는 작업 폴더 밖에 둔다, 그다음에 규칙을 건다.

</DeepDive>

<Lab session={7.5} title="미션 3 · 권한 읽고 좁히기" level="필수" minutes={25}>

<Step id="m7-6" title="내 예약 작업의 권한 읽기">

주간 브리핑 작업의 상세 화면을 엽니다. 권한 모드가 무엇인지, **Always allowed**에 무엇이 쌓였는지 읽습니다. 항목마다 "이 작업에 정말 필요한가"를 묻고, 설명할 수 없는 것은 거둡니다. 거둔 뒤 **Run now**로 돌려 그 요청이 다시 뜨는지 보면 무엇에 쓰이던 허용인지 알 수 있습니다.

</Step>

<Step id="m7-7" title="거부 규칙 하나를 걸고 시험하기">

## 4단계 한 줄로 실행하기

이 단계를 마치면 `claude -p` 한 줄의 옵션이 무엇을 허용하고 막는지 읽을 수 있습니다. 데스크톱 예약 작업만 써도 충분하니, 궁금한 분만 따라 하세요.

<DeepDive title="헤드리스 실행은 무엇이 다른가">

| | 데스크톱 예약 작업 | <Term id="headless">헤드리스 실행</Term> (`claude -p`) |
| - | - | - |
| 시작 | 앱이 시간에 맞춰 | 내가 명령을 치거나, 운영체제의 예약 기능이 |
| 승인 요청 | 멈춰 기다린다. 세션을 열어 답할 수 있다 | 답할 사람이 없다. 미리 허용하지 않은 것은 거부된다 |
| 권한 정하기 | 작업마다 권한 모드 | 명령의 옵션(`--permission-mode`, `--allowedTools`) |
| 기록 | 앱의 History | 스스로 남겨야 한다 |

완성본 스크립트가 쓰는 `dontAsk`는 터미널에서만 쓸 수 있는 권한 모드로, 물어봐야 하는 동작을 모두 거부합니다. 여기에 `--allowedTools "Edit(보낸문서/**)"`로 쓰기를 한 폴더에만 열어 준 것입니다. 지시문이 틀리더라도 `보낸문서/` 밖의 쓰기는 권한에서 한 번 더 막힙니다([문서](https://code.claude.com/docs/en/headless#auto-approve-tools)).

</DeepDive>

<Step id="m7-12" title="훅 한 개: 기다릴 때 알림 받기">

<Term id="hook">훅</Term>은 Claude Code가 정해진 시점에 **반드시** 실행하는 명령입니다. 지시문은 AI가 따르기로 하는 부탁이지만, 훅은 AI의 판단과 상관없이 그 시점이 오면 실행됩니다([문서](https://code.claude.com/docs/en/hooks-guide)). 문서의 첫 예시인 "입력이나 승인을 기다릴 때 알림"을 걸어 봅니다. 설정 문법은 Claude Code에게 맡기고, 선생님은 결과를 읽습니다.

<PromptCard id="hook-notify-setup" />

넣기 전에 보여 주는 내용은 이런 모양입니다.

```json
{
  "hooks": {
    "Notification": [
      { "matcher": "", "hooks": [{ "type": "command", "command": "(운영체제에 맞는 알림 명령)" }] }
    ]
  }
}
```

읽을 곳은 세 군데입니다. `Notification`은 언제(Claude가 입력이나 승인을 기다릴 때), 빈 `matcher`는 모든 알림에, `command`는 무엇을 실행할지입니다. `matcher`를 `permission_prompt`로 좁히면 승인 요청 때만 울립니다. 시험은 문서대로 합니다. Manual 모드에서 승인이 필요한 일을 시키고 다른 창으로 넘어가 알림이 오는지 봅니다. Windows 예시는 알림 대신 대화 상자를 띄우는데, 다른 창 뒤에 뜰 수 있습니다. 끄려면 추가한 블록을 지워 달라고 하면 됩니다.

훅은 알리는 일 말고 막는 일에도 쓰입니다(문서의 "Block edits to protected files" 예시). 이 과정에서는 소개만 합니다.

</Step>

## 5단계 자동화하면 안 되는 일

이 단계를 마치면 내 자동화 후보를 세 칸으로 나누고 까닭을 댈 수 있습니다.

| | 자동으로 해도 되는 일 | 초안까지만 | 자동화하면 안 되는 일 |
| - | - | - | - |
| 성격 | 내가 읽을 자료를 모으고 정리한다 | 다른 사람에게 나가기 전 단계를 준비한다 | 판단, 발송, 삭제 그 자체 |
| 학교의 예 | 주간 브리핑, 공문 기한 표 갱신, 이번 주 학사일정 뽑기 | 가정통신문·학급 안내문 초안, 회의록 초안, 공문함 정리 제안 | 점수 확정, 학교생활기록부 문장 작성과 나이스 입력, 학부모·학생에게 문자와 메일 발송, 업무포털 제출, 파일 삭제 |
| 사람의 자리 | 기록을 정해 놓고 읽는다 | 읽고 고치고 결재를 받아 내보낸다 | 처음부터 사람이 한다. 에이전트는 점검과 취합만 돕는다 |

어느 칸인지 헷갈리면 네 가지를 묻습니다. 하나라도 "예"이면 오른쪽으로 한 칸 옮깁니다.

1. 평가나 기록의 **판단**이 들어가는가
2. 학부모, 학생, 다른 기관으로 **나가는가**
3. **되돌릴 수 없는가**
4. **학생 개인정보**를 읽어야 하는가

<Callout type="warn" title="학교생활기록부는 초안도 자동으로 쌓아 두지 않습니다">
  「2026학년도 학교생활기록부 기재요령(고등학교)」은 AI로 생성한 자료를 서술형 항목에 그대로 입력하는 행위를 신뢰도를 떨어뜨리는 사례로 듭니다([학교생활기록부 종합 지원포털](https://star.moe.go.kr/web/contents/m21100.do?schYr=2026)). 기록의 근거는 교사가 직접 관찰한 내용입니다. 예약 작업이 세특 문장을 미리 써 두게 하지 마세요. 해당 학년도 기재요령과 소속 교육청 지침을 확인하세요.
</Callout>
