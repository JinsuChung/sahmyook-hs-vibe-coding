## 운영 형태

기준은 **회차당 50분(한 차시), 8회차**입니다. 회차 페이지의 실습 시간(Lab의 분)은 이 기준에 맞춰 두었습니다. 필수 실습만 해도 22–27분이라 개념과 시연을 15–18분 안에 끝내야 합니다. 개념이 길어지면 실습을 줄이지 말고 <b>자세히</b> 상자와 깊이 파기로 넘기세요.

### 두 회차를 묶어 2시간 연수 4회로

120분 = 회차 50분 × 2 + 쉬는 시간 10분 + 여유 10분으로 잡습니다. 묶음마다 줄일 것은 아래와 같습니다.

| 묶음 | 줄이거나 옮길 것 | 여유 10분을 쓸 곳 |
| --- | --- | --- |
| 1 + 2 | 2회차의 "과제 공유"는 생략하고, 1회차 끝에 반복 업무 3가지를 그 자리에서 3분 동안 메모. 2회차 개념의 컨텍스트·되돌리기는 표만 보여 주고 깊이 파기 1.5로 | 설치·로그인이 늦은 수강생 따라잡기 |
| 3 + 4 | 3회차 시연의 빌드 에러 장면은 4회차로 미룸. 4회차 선택 실습 "배포본에도 열쇠 넣기"를 3회차 배포에 바로 이어 붙이면 흐름이 자연스러움. `npm install`은 한 번만 설명 | GitHub 로그인 연동, Supabase 가입 지연 |
| 5 + 6 | 5회차 과제(내 업무 지도)는 6회차 끝에 한 번만 안내. 6회차 "눈대중으로 물어보기"(6-2)는 강사 시연으로. 쉬는 시간에 5-3(공문 요약 스킬)을 못 한 사람은 완성본의 `doc-digest` 폴더를 복사 | `.claude` 폴더 승인 창, 새 대화 열기 |
| 7 + 8 | 7회차 심화(한 줄로 실행하기)는 생략하거나 화면만 보여 줌. 8회차 실습 3(배포)은 강사 시연으로. 캡스톤은 사후 과제 | 예약 작업 화면이 문서와 다를 때, API 키가 없는 수강생 짝짓기 |

2시간 묶음에서는 사전 준비가 두 회차 치입니다. 특히 3 + 4는 계정 네 개(GitHub, Vercel, Supabase, Claude Console)와 Git·Node.js가 한꺼번에 필요하므로, 일주일 전에 준비 체크리스트를 따로 공지하세요.

### 깊이 파기(n.5) 안내

- 매 회차 끝 30초: 다음 n.5 페이지를 화면에 띄워 단계 다섯 개와 걸리는 시간을 보여 줍니다. "공강 시간에 한 단계씩"이라고 말해 주면 부담이 줄어듭니다.
- 다음 수업 시작 3–5분: 각 n.5 끝의 "다음 수업에서 물어볼 것"을 2–3명에게 듣습니다. 복습과 질의응답을 겸합니다.
- 깊이 파기는 선택입니다. 하지 않은 수강생이 다음 회차에서 막히지 않도록, 다음 회차에 **꼭 필요한 준비**만 따로 말해 줍니다(아래 표).
- 2시간 묶음으로 운영하면 n.5 두 개(약 3시간 분량)가 한 주에 몰립니다. 필수 미션만 골라 안내하세요.

| 깊이 파기 | 다음 회차에 꼭 필요한 것 | 시간이 없으면 이것만 |
| --- | --- | --- |
| 1.5 | Python 설치 확인, 2회차 자료 내려받기 | 미션 2(아쉬운 지시와 좋은 지시), 한글(HWP) 요령 읽기 |
| 2.5 | GitHub 가입, Git·Node.js 설치, 계산기 폴더 확인 | 미션 2(검증 기준), 미션 9(3회차 준비) |
| 3.5 | Supabase·Claude Console 가입 | 미션 2(되돌리는 세 가지 방법) |
| 4.5 | 5회차 시작 자료 내려받기, 앱 업데이트 | 미션 2(RLS 두 계정 시험), 개인정보 점검표 |
| 5.5 | `home-letter`·`doc-digest`가 든 교무수첩 폴더, Python 확인 | 미션 3(업무 지도. 5회차 과제와 같은 칸) |
| 6.5 | 앱 최신 버전, `보낸문서/공문_할일표.md` | 미션 2(스크립트 옵션, 기준 문서 직접 고치기) |
| 7.5 | 8회차 완성본, Console 한도, 내 단원과 학습 목표 메모 | 미션 3(권한 읽기), 5단계 표(자동화하면 안 되는 일) |
| 8.5 | 없음(과정 이후 4주) | 1주차 운영 계획 한 장 |

## 수업 전 준비 체크리스트

학교와 협의할 것은 **정보부장, 전산 담당 선생님**과 연수 2주 전까지 끝냅니다.

- [ ] Claude 계정: 수강생 개인 Pro인지, 학교 단위 계약(Team 등)인지. 무료 플랜에는 Claude Code가 없습니다. 개인 계정이면 데이터 설정(모델 학습 허용 여부)을 각자 확인하게 안내
- [ ] API 크레딧(4·8회차): 누가 부담하는지. 수강생 각자 소액 충전, 학교 예산, 강사 키로 시연만 하는 방식 가운데 하나로 미리 결정
- [ ] 실습 기기: 학교 업무용 PC인지 개인 노트북인지. 업무용 PC라면 학생 정보가 든 폴더를 열지 않도록 실습용 폴더를 따로 만들게 안내
- [ ] 설치 권한: Claude 데스크톱 앱(1회차), Python(2회차), Git·Node.js LTS(3회차). 설치가 막힌 PC는 전산 담당에게 목록을 전달([설치 가이드의 학교 PC 항목](/start/setup#school-pc))
- [ ] 학교 무선망·보안 프로그램: claude.ai, api.anthropic.com, github.com, vercel.com, supabase.co, npm 내려받기가 열리는지 실습 장소에서 직접 확인. 막히면 강사가 쓸 망을 따로 준비
- [ ] 실습 PC 1대(가능하면 Windows)로 **전 회차 리허설**. 아래 "강사가 실제로 돌려 확인해야 하는 것"을 이때 함께 확인
- [ ] 자료실 zip 9개가 Windows 기본 압축 풀기에서 한글 파일 이름이 깨지지 않고 풀리는지 확인
- [ ] 회차별 사전 과제 공지: 홈과 과정 소개의 준비 체크리스트(`prep-1` – `prep-8`) 링크를 회차 사흘 전에 보냄
- [ ] 시연 백업: 네트워크가 끊겨도 보여 줄 수 있게 핵심 시연(1회차 폴더 정리, 3회차 배포, 5회차 `/home-letter`, 7회차 Run now, 8회차 튜터)을 미리 녹화
- [ ] 교육용 API 키: 나눠 줄 경우 키마다 낮은 월 한도, 수업 직후 폐기 일정, 폐기 담당자. 키는 메신저나 이 페이지에 적지 않음
- [ ] 8회차용 수업 코드는 수업 직전에 정하고, 끝나면 바꾸거나 배포를 내림
- [ ] 실제 학생에게 튜터를 쓰는 일은 이 연수의 범위가 아님을 학교 관리자와 미리 공유(교사끼리 시험하는 데까지)

## 수업 전에 강사가 실제로 돌려 확인해야 하는 것

<Callout type="warn" title="완성본과 키트에는 끝까지 실행해 보지 못한 부분이 있습니다">
  이 사이트의 완성본 웹앱과 교무수첩 키트는 문서와 대조하고 가짜 서버로 동작을 확인했지만, 실제 Claude API, Supabase, Vercel, `claude` 실행으로 끝까지 시험하지는 못했습니다. 본문에서 "(예시)"라고 적힌 예상 결과가 그런 곳입니다. 근거는 `scripts/samples-manifest.md`의 "확인하지 못한 것"과 `scripts/workspace-manifest.md` 14절입니다. 아래를 수업 전에 직접 돌려 보고, 결과가 본문과 다르면 본문의 예상 결과를 고치세요.
</Callout>

| 회차 | 돌려 볼 것 | 확인할 점 |
| --- | --- | --- |
| 4 | 완성본에 실제 Supabase 프로젝트 연결: `schema.sql` 실행, 교사 계정 2개, 로그인, 등록·수정·삭제 | 표와 10줄이 생기는가. `permission denied for table assessments`가 나오면 본문 "막혔을 때"의 grant 문으로 풀리는가 |
| 4 | RLS 두 계정 시험(깊이 파기 4.5 미션 2) | 남이 등록한 평가의 수정·삭제가 막히고 안내 문구가 본문과 같은가. 공개 키로 직접 추가가 거부되는가 |
| 4 | 실제 API 키로 `평가계획/` 문서 3개 추출 | 7건이 정답표와 같은가. 통합과학 문서에서 빨간 경고가 뜨는가. 담당 교사가 `관리자`로 바뀌지 않는가 |
| 4 | Vercel 배포와 환경변수, Redeploy | 배포 주소에서 로그인과 추출이 되는가 |

| 6 | 커넥터 메뉴 위치 | **+** → **Add connectors**, 사이드바 **Customize** → **Connectors**가 지금 앱과 같은가 |
| 7 | 로컬 예약 작업 만들기, **Run now**, **History**, **Always allowed** | 화면이 **Scheduled**인지 **Routines**인지, 양식의 칸 이름이 본문 7-4와 같은가. Manual 모드에서 멈춰 기다리는가 |
| 7 | 헤드리스 스크립트 `run-weekly.sh` | 한글 경로가 든 `--allowedTools "Edit(보낸문서/**)"` 규칙으로 저장이 되는가. 거부되면 본문의 대안(`acceptEdits`)으로 설명 |

| 8 | Vercel에 올린 튜터 | 글자가 흘러나오듯 보이는가, 횟수 제한 문구가 뜨는가 |

| 전체 | 데스크톱 앱의 메뉴 이름 | 모드 칸의 **Manual / Accept edits / Plan / Auto**, **Local**, <b>Open folder…</b>, **+ New**, `/rewind`, `/reload-skills`가 본문과 같은가 |
| 전체 | Windows 기본 압축 풀기 | zip 9개 모두. 특히 한글 폴더 이름과 `.claude` 숨김 폴더 |

AI의 답은 실행할 때마다 표현이 다릅니다. 리허설에서는 문장이 아니라 숫자와 행동이 본문과 같은지를 보세요.

## 우리 반 진행 현황 (별명 참여)

- 1회차 실습을 시작하기 전에 홈 화면의 **별명으로 참여하기**를 다 같이 누릅니다(1분). 참여한 뒤 실습 단계를 체크하면 홈 현황판에 바로 모입니다.
- **실명이나 교번 대신 별명**을 쓰게 안내합니다. PIN에는 다른 곳에서 쓰는 비밀번호를 쓰지 않습니다.
- 수업 중 홈의 현황판을 띄워 "지금 몇 명이 1회차를 끝냈는지" 보여 주면 참여가 올라갑니다. 순위는 보여 주지 않고 완료 소식만 띄웁니다.
- 기록 위치: Vercel → Storage → Blob `sahmyook-hs-vibe-progress` → `class/production/participants/` (참가자 1명이 파일 1개, 파일 이름은 별명 해시)
- 저장되는 것은 별명, 암호화한 PIN, 실습 체크 현황뿐입니다. 과제 칸에 쓴 글은 서버에 저장되지 않습니다.
- 시험 삼아 만든 기록 지우기: 본인이 사이드바의 **내 기록 지우기**를 쓰거나, 강사가 위 폴더에서 해당 파일을 지웁니다.
- 다음 기수를 시작하기 전에 위 폴더의 파일을 모두 지웁니다. 로컬 개발 기록은 `class/dev/`, 미리보기 배포 기록은 `class/preview/`에 따로 쌓입니다.

- **미성년자 관련 설명의 강도**: Anthropic 가이드라인에서 "반드시" 하라고 한 것은 AI와 대화하고 있음을 알리는 일입니다. 연령 확인, 내용 걸러 내기, 모니터링과 신고 수단, 안전 사용 교육 자료는 갖추어야 할 추가 안전장치의 **예**로 들고 있습니다. 법적 의무처럼 단정해 말하지 말고, 운영 전에 원문과 학교·교육청 지침을 직접 확인하라고 안내합니다. 이 과정은 법률 자문이 아닙니다.
- **예상 질문**
  - "학생에게 Claude를 쓰게 해도 되나요": Claude.ai는 만 18세 이상만 가입할 수 있습니다. 계정을 만들게 하거나 교사 계정을 빌려주면 안 됩니다. 학생이 직접 쓰는 도구는 교사나 학교가 API로 만든 앱의 형태가 되고, 운영하는 쪽이 책임집니다.
  - "오늘 만든 튜터를 내일 수업에 써도 되나요": 오늘 주소는 교사끼리 시험하는 데까지입니다. 실제 수업에 쓰려면 학교 관리자·정보 담당 선생님과 협의하고, 학교 절차에 따라 학생·학부모 안내를 마친 뒤, 교사가 함께 있는 시간에만 엽니다.
  - "학생 대화를 나중에 볼 수 있나요": 볼 수 없습니다. 저장하지 않기 때문입니다. 새어 나갈 것이 없는 대신 모니터링 수단도 없습니다. 기록이 필요하면 코드를 고치기 전에 개인정보 처리 근거와 고지, 보관 기간을 학교 절차로 먼저 정해야 합니다.
  - "비용은 얼마나 드나요": 완성본 README의 어림으로 한 반 28명이 한 차시 쓰면 Haiku 5.5 기준 보통 1달러에 못 미칩니다. 어림일 뿐이므로 Console의 월 사용 한도를 먼저 걸고, 첫 사용 뒤 실제 사용량을 확인합니다. 비용을 누가 부담할지는 학교와 정합니다.
  - "튜터의 답을 평가나 생기부 근거로 써도 되나요": 쓰지 않습니다. 평가와 기록의 판단은 교사가 합니다.
